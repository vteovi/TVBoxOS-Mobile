## GoProxy 原生库崩溃修复（订阅"王小二（在线）"报错）

- 现象：`UnsatisfiedLinkError: dlopen failed: .../.libwexproxylbUv4rSjA8 has bad ELF magic: 3c3f786d`，`3c3f786d` = `<?xm`，说明下载到的不是 `.so` 而是 XML 错误页。
- 根因：App 的 spider JAR 是运行时从订阅的 `spider` 地址动态下载、DexClassLoader 加载的；GoProxy 原生库在该 JAR 内部下载并 `System.load`。该远程 so 地址失效/被拦截，返回 XML → dlopen 失败。属远程/订阅问题，App 源码无法修那个地址。
- 修复：`app/src/main/java/com/github/tvbox/osc/base/App.java` 的 `initCrashConfig()` 在 Caoc 之后包一层 `Thread.setDefaultUncaughtExceptionHandler`：
  - 仅后台线程上，对"原生库损坏"类崩溃（`bad ELF magic`/`has bad ELF`/`libwexproxy`/`GoProxy`）静默忽略 + 清理 `files/TV/` 下损坏 `.so`；主线程仍交 Caoc 处理，避免主线程被静默放死。
  - 这样不弹报错页、不闪退，订阅里不依赖 GoProxy 的源仍可正常使用。
  - 改进（第二轮）：`cleanCorruptNativeLibs()` 改为只读文件头 4 字节，仅删未以 ELF 魔数(`7F 45 4C 46`)开头的隐藏 `.lib` 文件，不再误删正常 `.so`；并在 `onCreate` 加载订阅源前 `cleanCorruptNativeLibs()` 预清理一次。
  - 触发场景不止订阅：设置里切换主题色也会重新初始化蜘蛛/config、后台线程起 GoProxy，同样崩——属同一根因。
  - 关键：改的是源码，手机跑的是旧包；必须重新 `assembleDebug` 安装后才生效。用户两次崩溃均为未重新打包。
  - 编译踩坑：ImmersionBar 3.2.2 里导航栏深色图标方法是 `navigationBarDarkIcon(boolean)`，**不是** `navigationBarDarkFont`（那是状态栏的）。最初三处写错导致 `compileDebugJavaWithJavac` 失败，已全部改为 `navigationBarDarkIcon`。
  - 已成功 `assembleDebug`：产物 `app/build/outputs/apk/debug/TVBox-Mobile-v2.1.26.apk`（约 45MB）。local.properties 已写入 `sdk.dir=C:\\Android\\Sdk`。
- 提示用户：该订阅是否能完整解析取决于源是否强依赖 GoProxy；必要时换一个可用的 spider JAR 地址（订阅 config 的 `spider` 字段）。

## 底部"窄白条"真正的根因与最终修复（用户反馈第一次没修好）

- 现象：底部导航栏**最贴屏幕底边**有一条"特别白"的窄条（不是全宽底栏本身）。
- 定位手段：`adb shell dumpsys window windows` 看到
  - `GestureStub mFrame=[0,2365][1080,2400]` → 手势导航区 = y2365–2400（就是那条窄条）；
  - MainActivity `mFrame=[0,0][1080,2400]` / `Requested 1080x2400` → **App 窗口铺满全屏(全面屏/edge-to-edge)**。
- 真正根因（第一次改错的原因）：
  - 系统导航栏是**画在 App 内容之上**的一层。App 底栏背景 `bg_bottom_navigation=#B3FFFFFF`(70%白)，窗口透明(ImmersionBar 使窗口透明→系统壁纸透出)。
  - 原来导航栏色 = `R.color.white`(**不透明**纯白) → 盖住壁纸 → 死白条。
  - 第一次我改成 `bg_bottom_navigation`(#B3FFFFFF) → 相当于在 70% 白的底栏上**再叠 70% 白**，合成≈91% 白 → 反而更白，仍是条。
  - **正解：系统导航栏设为完全透明**，直接露出 App 自带底栏，二者一致 → 无缝。
- 最终修改：`BaseActivity.initStatusBar()` 的 `navigationBarColor` 由 `R.color.bg_bottom_navigation` 改为新增的 `R.color.transparent`(#00000000)，保留 `navigationBarDarkIcon(!Utils.isDarkTheme())`。
- 新增：`app/src/main/res/values/colors.xml` 加 `<color name="transparent">#00000000</color>`。
- 已 `assembleDebug` 并 `adb install -r` 到 M2007J17C 验证(全面屏下不再有独立白条)。
- 经验：系统导航栏/状态栏这类系统栏是叠加在 App 之上的图层，设"半透明白"会与下面的半透明底栏二次合成→更白；要"融为一体"应设**完全透明**。

## 首页滑动逻辑调整（滑动分栏而不是跳到"我的"）
- 需求：首页右→左滑动会整页切到"我的"，用户希望滑动只在首页内部的分栏(TabLayout各分类)之间生效。
- 结构：`MainActivity` 外层是 `androidx.viewpager2.widget.ViewPager2`(`mBinding.vp`)，仅 2 页 = HomeFragment(0) / MyFragment(1)，左右滑=切"首页/我的"；`HomeFragment` 内层是旧版 `androidx.viewpager.widget.ViewPager`(`mBinding.mViewPager`)+`DslTabLayout`，由 `ViewPager1Delegate.install(...)` 绑定=首页分栏。
- 根因：嵌套横滑时**外层 ViewPager2 抢手势**，内层分栏滑不动、整页跳到"我的"。
- 修复：`MainActivity.init()` 设置 `mBinding.vp.isUserInputEnabled = false`（关闭外层手势滑动）。切"我的"仍可用底部导航按钮；`setCurrentItem` 程序化切换与 `onPageSelected` 回调均不受影响。

## 签名问题（"每次安装都要先卸载"的根因）
- 现象：安装我们的包时提示签名不一致，必须 `adb uninstall` 后才能装。
- 根因：`app/build.gradle` 期望项目根目录的 `TVBoxOSC.jks`（alias/key/store 口令默认都是 `TVBoxOSC`），但该文件**被 `.gitignore` 的 `*.jks` 忽略、下载包里没有** → `tvBoxSigningStore.exists()==false` → signingConfig 为空 → debug 构建回退到默认 Android 调试证书（实测 APK 签名 `CN=Android Debug`, SHA-256 `a4d29713...`）。官方 release 包是用维护者的 `TVBoxOSC.jks` 签的，两者证书不同 → Android 只允许**同签名**覆盖升级，故必须卸载。
- 注意：没有 keystore 时 `assembleRelease` 会产出**未签名**APK（release 分支仅在 store 存在时才设 signingConfig）。
- 结论/建议：官方 keystore 不在仓库里，无法让我们的包直接覆盖官方包；要么拿到官方 `TVBoxOSC.jks`，要么用自建 keystore 统一签名（debug/release 一致），并**始终只装自己编的包、别再和官方包混装**，卸载一次后即可持续覆盖安装。

## 方案A 落地：新增项目签名 TVBoxOSC.jks
- 用 keytool(JDK17) 生成根目录 `TVBoxOSC.jks`（`-storetype PKCS12`，alias/keypass/storepass 均 `TVBoxOSC`，RSA2048，有效期 10950 天）→ `build.gradle` 的 `tvBoxSigningStore.exists()` 成立，debug/release 均使用该签名。
- `./gradlew assembleDebug assembleRelease` 成功（约 14 分钟，含 release 变体首次编译）。
- 校验：debug 与 release 两个 APK 的签名 DN 均为 `CN=TVBoxOSC,...`、SHA-256 `4a568ad4b7ca8888eb3af2dbb2ec5c472a4538da60d9f5775e8488e52f7a4282`（一致）。
- 产物：`app/build/outputs/apk/debug/TVBox-Mobile-v2.1.26.apk`(45MB)、`app/build/outputs/apk/release/TVBox-Mobile-v2.1.26.apk`(42MB)。
- 注意：设备上现装的旧调试包是 `CN=Android Debug` 签名，与新的 TVBoxOSC 签名不同 → **仍需最后卸载一次**，之后所有同签名包可一直覆盖安装，不再需要卸载、也不再丢数据。
- `.gitignore` 含 `*.jks`，该密钥不会入库。

## 订阅失败 + 首页只剩"主页"栏（Android 14+ 动态 dex 加载限制）
- 现象（Android 16 手机 25053RT47C）：提示订阅失败，且首页只有"主页"一栏，其它分类不显示。
- 诊断：`adb logcat` 抓到致命错误
  `java.lang.SecurityException: Writable dex file '/data/user/0/com.github.tvbox.osc/files/csp.jar' is not allowed.`
  at `dalvik.system.DexClassLoader.<init>` ← `com.github.catvod.crawler.JarLoader.loadClassLoader(JarLoader.java:49)`
  ← `ApiConfig.loadJar(ApiConfig.java:251)` ← `HomeFragment.loadJar`（"更新订阅失败" toast）。
- 根因：`targetSdk 34` 起 Android 14+ **禁止从可写目录用 DexClassLoader 加载 dex/jar**。项目把 `csp.jar` 下到 `files/`(可写) 再 `DexClassLoader` → 被拦 → spider 加载失败 → 分类为空 → `adjustSort(空, withMy)` 只剩"主页"。
- 修复（`app/src/main/java/com/github/catvod/crawler/JarLoader.java` + `JsLoader.java`）：
  - JarLoader 新增 `public static createClassLoader(jar, optDir)`：`SDK_INT >= 26` 时用 `readDexBuffers()` 从 jar/zip 中取出根目录所有 `classes*.dex`（也兼容裸 dex），转成**直接内存 ByteBuffer**，用 `InMemoryDexClassLoader` 加载；否则回退 `DexClassLoader` + `setReadOnly()`。
  - 类型由 `DexClassLoader` 改为 `BaseDexClassLoader`（map / loadJarInternal / getSpider / jsonExt / jsonExtMix）。
  - `JsLoader.loadClassLoader` 同样改为调用 `JarLoader.createClassLoader(...)`（JS 蜘蛛同源问题）。
- 验证：覆盖安装 release 包后 `adb logcat` 出现 `D: SpiderLog: 自定义爬虫加载成功！` / `I/System.out: 自定义爬虫代码加载成功!`，且不再有 `Writable dex file`；截图确认首页已显示多个分栏（热门电影/热播剧集/热播综艺/电影筛选/电视筛选…）并加载出内容。
- 注：安装已无需先卸载（新包与手机上的包同为 TVBoxOSC 签名，`adb install -r` 直接成功）。
