## 首页"更新订阅失败"修复 + 版本升至 2.1.27

- 现象：手机首页弹"更新订阅失败"，且首页分类不全（只剩"主页"）。
- 定位：该 toast 全项目唯一来源 = `HomeFragment.loadJar()` 的 `callback.error()`（204 行）。上游只有两条：
  1. `ApiConfig.loadJar` 下载失败；
  2. `JarLoader.load()` 返回 false。
  两者都归结到 `JarLoader.loadClassLoader()` 返回 false。
- **根因（真 bug）**：`loadClassLoader()` 原来把 `Init.init()` 的成败也算进 `success`：
  ```java
  classInit = classLoader.loadClass("com.github.catvod.spider.Init");
  if (classInit != null) {
      method.invoke(null, App.getInstance());   // ← 抛异常则 success 一直为 false
      success = true;                           // ← 永远走不到
  ```
  jar 里的 `Init` 会运行时下载 GoProxy 等原生库；昨天日志已记录该下载拿到 XML 错误页（`bad ELF magic: 3c3f786d`）。只要它抛错，整个类加载器都不会 `put` 进 map → `getSpider` 全部返回 `SpiderNull` → 首页只剩"主页" + 弹"更新订阅失败"。
- 修复 1（`app/src/main/java/com/github/catvod/crawler/JarLoader.java`）：拆成三步，成败只看 dex：
  - 第一步 `loadClass("com.github.catvod.spider.Init")`（带 5 次重试，兼容异步 dex 加载），成功即 `success=true` + `classLoaders.put(key, classLoader)` + 打印 `自定义爬虫代码加载成功!`；
  - 第二步 `Init.init()` 单独 try/catch，失败只打印"自定义爬虫 Init 初始化失败(仅影响依赖它的源, 订阅仍可用)"；
  - 第三步 `Proxy` 可选，失败忽略。
  - 关键点：`loadClass` 找不到类会抛 `ClassNotFoundException` 而不是返回 null，循环用 null 判断即可。
- 修复 2（`app/src/main/java/com/github/tvbox/osc/api/ApiConfig.java`）：缓存 `files/csp.jar` 加载失败时 `cache.delete()` 并回退到重新下载，避免坏缓存把失败变成永久状态。
- 修复 3：补诊断日志 `csp.jar 加载失败: <path> 大小=<> 来源=<>` / `csp.jar 下载失败: <url> -> <msg>`（大小异常小或非 zip/dex = 下到的是错误页）。
- 踩坑：`ApiConfig.loadJar` 里 `jarUrl` 被 `jarUrl.replace("img+","")` 重新赋值，不是 effectively final，匿名内部类直接引用会编译失败 → 先取 `final String jarUrlLog = jarUrl;`。
- 版本：`app/build.gradle` → `versionCode 237` / `versionName '2.1.27'`。`update.json` 与 README 由 `scripts/sync_release_metadata.sh` 在打 tag 发版时自动同步，**不要手改**。
- 构建：沙箱内 `processDebugResources` 被拦截（读 `C:\Users\VTE\.gradle\caches\...` 被拒），改为沙箱外执行 → `BUILD SUCCESSFUL in 8m 53s`。
- 产物：`app/build/outputs/apk/debug/TVBox-Mobile-v2.1.27.apk`（44MB），签名 `CN=TVBoxOSC` / SHA-256 `4a568ad4...`（与在装包同签名，可直接 `adb install -r` 覆盖）。

## 第二轮：分栏消失(死锁) + 底部导航栏改版

### 首页分栏"一个都没有" → spThreadPool 单线程自锁死
- `SourceViewModel` 里 `spThreadPool = Executors.newSingleThreadExecutor()` 是**静态单线程池**，且被 getSort/getList/getDetail/getPlay/getSearch 共用。
- 死锁路径：`getSort(type=3)` 自身提交到 spThreadPool（137 行）→ 任务内部在 `Hawk.get(HOME_REC)==1` 且 homeContent 无视频列表时调用 `getHomeRecList()`（115 行）→ 后者又 `spThreadPool.execute(...)`（381 行）。新任务排在当前任务之后永远不执行，而当前任务在等它的回调 ⇒ **回调永不触发**。
- 后果有两层，第二层更狠：① `sortResult` 不回调 → 观察者不执行 → `initViewPager` 不执行 → **首页一个分栏都没有**（连"主页"都没有，因为 adjustSort 的 withMy 分支压根没跑到）；② spThreadPool 被永久占死 → 之后所有 category/detail/play 请求全部排队不执行。
- 修复：新增 `homeRecThreadPool = Executors.newSingleThreadExecutor()`，`getHomeRecList` 改用它（381 行）。**注意：只要是从 spThreadPool 内部再往 spThreadPool 提交，就必然死锁，以后加代码别踩。**
- 兜底：`HomeFragment` 新增 `sortTimeoutTask`，`getSort` 后 20s 仍无结果且 `mSortDataList` 为空则 `postValue(null)`，强制渲染"主页"栏（观察者里 `mHandler.removeCallbacks` 取消）。

## 第四轮：直播页 NPE 崩溃（Activity 销毁后异步回调）

- 用户报的堆栈：`PlayerHelper.updateCfg(PlayerHelper.java:90)` ← `LivePlayerManager.getDefaultLiveChannelPlayer(:36)` ← `init(:32)` ← `LiveActivity.initLiveState(:915)` ← `parseProxyLiveContent(:876)` ← `LiveActivity$13.onSuccess(:853)`，`videoView` 为 null。
- 设备 crash buffer 时间戳 **14:08:50.571**，而用户操作序列里 `LiveActivity destroyed` 也在 **14:08:50** —— 同秒，铁证：**网络回调晚于 onDestroy 到达**。
- 根因链：`LiveActivity` 的直播源是单组 `http://127.0.0.1...` 代理源 → `initLiveChannelList()`(onCreate 206 行) 调 `loadProxyLives()` 发 OkGo 异步请求 → 用户 2 秒内返回/切页 → `onDestroy()`(344 行) `mVideoView.release(); mVideoView = null;` → 请求返回触发 `parseProxyLiveContent` → `initLiveState` → `livePlayerManager.init(null)` → NPE。
- 修复（4 个文件）：
  1. `PlayerHelper.updateCfg(VideoView, JSONObject)` 与 `updateCfg(VideoView)` 开头加 `if (videoView == null) return;`（最底层兜底）。
  2. `LivePlayerManager.getDefaultLiveChannelPlayer` 加 `videoView == null` 返回；`getLiveChannelPlayer` 加 `videoView == null || currentPlayerConfig == null` 返回。
  3. `LiveActivity.parseProxyLiveContent` / `initLiveState` / `showNoLiveChannels` 开头加 `if (isFinishing() || isDestroyed()) return;`，`initLiveState` 另加 `mVideoView == null`。
  4. `loadProxyLives` 的 OkGo 请求加 `.tag(this)`，`onDestroy` 里加 `OkGo.getInstance().cancelTag(this)`。
- 复现尝试（`am start LiveActivity` + `am start MainActivity --activity-clear-top` 触发 finish）：**旧包多次都未能复现**，因为本机 127.0.0.1 代理请求只需几十毫秒，比 adb 命令间隔（≥100ms）快，撞不进窗口。结论：这类竞争以堆栈+代码路径为准。
- 回归验证（新包）：冷启动后进直播页 6s，截图正常（央视IPV4/卫视IPV4/4K8K频道/历年春晚 + CCTV1..CCTV8 + 线路1/1）；快速进出 3 轮 + 无间隔 5 轮，`logcat -b crash` 无 FATAL，进程存活。截图：`C:\Users\VTE\AppData\Local\Temp\tvboxshots\live_after_fix.png`。

## 第五轮：首页分栏又消失 —— InMemoryDexClassLoader 拿不到 jar 内资源（第二轮修复引入的回归）

- 现象：首页只剩"主页"一栏，内容还是豆瓣热门；无崩溃、无"更新订阅失败"。
- 现场日志：`自定义爬虫代码加载成功!` 后紧跟
  `自定义爬虫 Init 初始化失败(仅影响依赖它的源, 订阅仍可用): java.lang.reflect.InvocationTargetException`
  完整 cause 链（`logcat --pid=<pid>` 导出后看到）：
  ```
  Caused by: java.lang.ExceptionInInitializerError
      at com.github.catvod.spider.DexNative.getLoader(Native Method)
      at com.github.catvod.spider.Init.init(Unknown Source:13)
  Caused by: java.lang.NullPointerException: ...'java.lang.Throwable.getMessage()' on a null object reference
      at com.github.catvod.spider.DexNative.<clinit>(Unknown Source:173)
  ```
  以及后续 `NoClassDefFoundError: com.github.catvod.spider.DexNative`
  @ `DouDouGuard.<init>` → `BaseSpiderGuard.<init>` → `Init.getSpider` → `JarLoader.getSpider(:265)` 返回 `SpiderNull`。
- 定位手段：拉取设备上的 `files/csp.jar`（`adb exec-out run-as ... cat`）→ 里面是 `classes.dex` + `assets/ftyguard_v7.so`/`ftyguard_v8.so` → `dexdump -d` 反汇编，看清 `DexNative.<clinit>` 的字节码：
  ```
  Init.deleteFilesWithFeature(cacheDir + separator, ".ftyfnw");
  abi = Build.CPU_ABI.contains("64") ? "v8" : "v7";
  File so = new File(cacheDir, ".ftyfnw" + Init.generateRandomString(10));
  InputStream in = Init.classLoader().getResourceAsStream("assets/ftyguard_" + abi + ".so");
  ...复制到 so...
  so.setReadOnly(); System.load(so.getAbsolutePath());
  catch (Exception e) { e.getCause().getMessage(); }        ← 二次 NPE
  ```
  且 `Init.<init>` 里 `this.oOo0oOo0Oo0oO0Oo = getClass().getClassLoader()` ⇒ `Init.classLoader()` 返回的正是 `JarLoader` 创建的那个类加载器。
- **根因（第二轮自己改出来的回归）**：`InMemoryDexClassLoader` 从 ByteBuffer 加载 dex，DexPathList 里没有 jar 路径 ⇒ `getResourceAsStream` 返回 null ⇒ `in.read()` NPE（被 catch）⇒ `e.getCause()` 也是 null ⇒ 二次 NPE ⇒ DexNative 类初始化失败 ⇒ 所有 `BaseSpiderGuard` 系源全线 SpiderNull。**Android 12 根本不需要 InMemory**（该限制只在 Android 14+ 生效），却也被套用了。
- 修复：
  1. `JarLoader.createClassLoader` 按 SDK 分支：`SDK >= 34` 才走内存加载，**`SDK < 34` 回到 `DexClassLoader` + `setReadOnly()`**（原版行为，DexPathList 自带 ZipFile，jar 内资源可读）。
  2. 新增 `crawler/JarResourceClassLoader`：继承 `ClassLoader`、`findClass` 抛 CNFE、只重写 `getResource`/`getResourceAsStream` 从 jar zip 条目读（读进内存后立即关 ZipFile），把它作为 `InMemoryDexClassLoader` 的 **parent**，给 Android 14+ 补回资源访问能力。
     - 注意：`InMemoryDexClassLoader` 是 **final**，不能继承（第一次尝试继承它直接编译失败：`无法从最终 InMemoryDexClassLoader 进行继承`），只能走"父加载器补资源"。
  3. `JsLoader` 复用同一方法，注释同步更正。
- 验证（M2007J17C，Android 12）：装机后连续两次冷启动 —— `自定义爬虫代码加载成功!`，**无** `Init 初始化失败`，`logcat -b crash` 无 FATAL；首页分栏恢复：`主页 / 热播电影 / 热播剧集 / 热播综艺 / 电影筛选 / 电视筛选 / 电影榜单 / 电视剧榜单`（比之前还全）。截图：`C:\Users\VTE\AppData\Local\Temp\tvboxshots\home_after_dexfix.png`、`home_after_dexfix_2nd.png`。
- 教训：**改类加载方式前先想清楚"谁依赖类加载器的非类能力（资源、路径）"**；`SDK >= 34` 的分支条件宁窄勿宽。
