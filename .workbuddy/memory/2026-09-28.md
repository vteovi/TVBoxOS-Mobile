## 搜索页进入自动弹键盘（已保留）
- 修复「首页搜索框进入搜索页后还要再点一次才弹键盘」：第一版只在 `init()` 里 `post{ requestFocus + showSoftInput }`，光标有了但 MIUI 上键盘不弹（SHOW_IMPLICIT 在窗口获得焦点前被忽略）。
- 修正方案（双层兜底，只针对无 `title` 进入）：
  1. `AndroidManifest.xml` 给 `FastSearchActivity` 加 `android:windowSoftInputMode="stateVisible"`（系统级，MIUI 可靠）。
  2. `FastSearchActivity` 在 `onWindowFocusChanged(hasFocus)` 里、窗口真正聚焦后、`entryKeyboardShown` 守卫下一次性 `KeyboardUtils.showSoftInput(etSearch)`；`init()` 仅保留 `post{ requestFocus() }` 让光标落在输入框。
- 注意：`UserFragment`/`GridFragment` 带 `title` 进来会走 `initData()` 自动搜索并 `KeyboardUtils.hideSoftInput`，所以自动弹键盘只在「无 title」分支做，避免覆盖自动搜索。`onWindowFocusChanged` 也用同一守卫。

## 「构建中断 → APK 用不了」处理
- 用户反馈构建的 APP 用不了，怀疑是 19:42 被 TaskStop 杀掉的那次 release 构建留下的半成品被拿去装了。
- 经检查磁盘上 20:08 重建后的 APK 完好（zip 1421 条目无损坏、dex/arsc 齐全、apksigner verify EXIT=0、versionCode 239）。
- 处理：删除输出 APK → 重跑 assembleRelease 强制重打包 → 全量校验（zip testzip + aapt2 badging + apksigner 退出码 + sha256）。
- **教训：TaskStop 杀掉 Gradle 后、或向用户交付 APK 前，必须删产物重建并校验（zip 完整性 + 签名退出码 + sha256），避免用户拿到写了一半的包。**
- 最终交付：`TVBox-Mobile-v2.1.29.apk`，42,419,924 字节，SHA-256 `c467b507...4f58c8`（完整值见当日构建输出），包含闪屏移除 + 搜索页自动弹键盘（stateVisible + onWindowFocusChanged）全部改动。
