## 平板"播放返回后变黑边小窗"修复（MIUI 兼容显示）
- 现象：小米/红米平板（MIUI/HyperOS）横屏握持时，播放视频返回后整个应用变成"横屏下显示竖屏内容"的兼容模式（居中小窗+两侧黑边），冷启动正常，重启才恢复。
- 根因：`PlayFragment.changedLandscape(false)`（退出全屏/预览）和 `PlayerTitleView` 返回键强制 `setRequestedOrientation(SCREEN_ORIENTATION_PORTRAIT)`；MIUI 平板在横屏下收到竖屏锁定请求会启用任务级粘滞的兼容显示，返回 `MainActivity`（本身支持任意方向）后不自动恢复。
- 修复（4 处）：
  1. `PlayFragment.changedLandscape(false)`：平板（`smallestScreenWidthDp>=600`）改 `SCREEN_ORIENTATION_UNSPECIFIED`，手机保持 PORTRAIT 原行为；
  2. `PlayerTitleView` 全屏返回键：同样按平板分支 UNSPECIFIED；
  3. `MainActivity.onResume()`：兜底 `requestedOrientation = UNSPECIFIED`，清除任何遗留固定方向请求；
  4. Manifest `<application>` 加 `android:resizeableActivity="true"`，显式声明支持任意尺寸，降低 MIUI 启用兼容显示的概率。
- 用户未指定版本号变动，维持 2.1.30；不代编译（用户此前明确"编译由我来进行"）。
- 可复用规则：**凡平板 MIUI 上涉及 setRequestedOrientation 的地方，退出播放/全屏时一律用 UNSPECIFIED 而非 PORTRAIT**（保留在 PlayFragment/PlayerTitleView 注释里）。
- 坑：本工程依赖的 blankj utilcode 版本**没有** `ScreenUtils.isTablet()`（编译报"找不到符号"）。判定平板改用 Android 标准 `resources.configuration.smallestScreenWidthDp >= 600` 内联，不要再用 `ScreenUtils.isTablet()`。

## gradle.properties 构建内存/并行度上限（应对 7.9G 内存机器编译卡顿）
- 根因：默认 `org.gradle.jvmargs=-Xmx2048m` 且无 `workers.max` 限制，Gradle 按 CPU 核心数开并行 worker + 可能独立 Kotlin 守护进程，瞬时吃满内存/CPU 致系统卡。
- 现配置（项目根 `gradle.properties`）：
  - `org.gradle.jvmargs=-Xmx1536m -Xms384m -XX:MaxMetaspaceSize=512m -XX:+UseG1GC -XX:MaxGCPauseMillis=200`（7.9G 机器降到 1.5GB 堆）
  - `org.gradle.workers.max=2`（默认=CPU 核心，限制并行降占用；若仍卡改 1，编译更慢）
  - 弃用 `kotlin.compiler.execution.strategy=IN_PROCESS`：Kotlin Gradle 插件只认大写枚举 `IN_PROCESS`，旧守护进程可能缓存小写 `in_process` 导致 "Unknown value 'in_process'" 编译失败（build_apk.bat 重跑仍复现），且该属性跨版本脆弱。已移除。
  - 改用默认 OUT_OF_PROCESS（独立 Kotlin 守护进程）+ `kotlin.daemon.jvmargs=-Xmx1024m -Xms256m` 单独限制守护进程内存，与 Gradle 主 JVM 的 -Xmx1536m 形成双上限，总峰值约 2.5GB，7.9G 机器不卡。
  - 教训：`build_apk.bat` 的 `:run_build` 开头已加 `call gradlew.bat --stop`，每次构建前清掉残留守护进程，防止旧配置缓存导致"改了 gradle.properties 却不生效/报错"。
- 8GB 档经验值：`-Xmx1536m` + `workers.max=2` 够用且不卡；16GB+ 可提到 `-Xmx3072m` / `workers.max=3~4`。
