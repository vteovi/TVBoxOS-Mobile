## 大屏导航编译失败修复（同日下午）
- 报错：`layout-sw600dp/include_bottom_navigation.xml` `app:orientation` attribute not found（链接期，非编译期）。
- 根因：`BottomNavigationView` **没有** `app:orientation` 属性（之前 aapt2 compile 只校验语法漏掉链接）。
- 修复：`include_bottom_navigation.xml` 改用 `NavigationRailView`（`com.google.android.material.navigationrail.NavigationRailView`，自带竖向左导航），删 `app:orientation`；三页 Activity 把 `bottom_nav` 强转由 `BottomNavigationView` 改为公共基类 `NavigationBarView`（手机端仍是 BottomNavigationView，大屏为 NavigationRailView，二者都继承之）。
- 教训：XML 资源改动不能只靠 `aapt2 compile` 自检，属性是否存在要在 `processReleaseResources` 链接阶段才暴露；竖向左导航应用 NavigationRailView 而非给 BottomNavigationView 加 orientation。

## 直播页：平板锁横屏 + 隐藏导航栏（提交 24c0c0d）

  触发 MIUI 兼容显示(两侧大黑边小窗)。根因：LiveActivity 清单无 screenOrientation；PlayerTitleView 退出全屏对

- 改动：
  1) LiveActivity.init() 平板(smallestScreenWidthDp>=600)进入即 setRequestedOrientation(SCREEN_ORIENTATION_SENSOR_LANDSCAPE)。

  3) PlayerTitleView 退出全屏平板分支 UNSPECIFIED→SENSOR_LANDSCAPE（该类现仅 LiveActivity 使用，不影响点播）。手机分支维持 PORTRAIT。
- 判定平板统一用 Configuration.smallestScreenWidthDp>=600（blankj ScreenUtils 无 isTablet）。

## 平板直播页横屏锁定（收尾修复）—— 提交 f9a31b6
- 现象：平板（小米平板5+）直播页「全屏→半屏」被强制竖屏，触发 MIUI 兼容显示（内容居中、两侧大块空白）。
- 上次只改了 PlayerTitleView 标题栏返回一条路径，不够。退出全屏有多条路径最终都调 activity.setRequestedOrientation() 请求竖屏：
  - 返回键：LiveActivity.onBackPressed → VideoView.onBackPressed → LiveNewController.onBackPressed →
    player 库 BaseVideoController.stopFullScreen()（419-421 行硬编码 SCREEN_ORIENTATION_PORTRAIT）；
  - dkplayer-ui（外部 AAR dkplayer-ui:3.3.5）的 LiveControlView 全屏按钮 → ControlWrapper.toggleFullScreen(activity) → PORTRAIT；
  - 方向传感器 onOrientationPortrait → PORTRAIT；
  - UNSPECIFIED 在小米平板上也会被解析成竖屏。
- 修复：在 LiveActivity **重写 setRequestedOrientation()**，平板（smallestScreenWidthDp>=600）下把「可能变竖屏」的取值
  （UNSPECIFIED/SENSOR/USER/FULL_SENSOR/FULL_USER/PORTRAIT/SENSOR_PORTRAIT/REVERSE_PORTRAIT/USER_PORTRAIT）
  统一改写为 SENSOR_LANDSCAPE。单点拦截覆盖全部路径，手机端行为完全不变。
- 心得：这类「多处调用最终汇流到同一 API」的场景，与其逐个 call site 打补丁，不如在最外层 Activity 重写该方法统一拦截。
