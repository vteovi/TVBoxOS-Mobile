# 2026-10-18 工作日志

## 新增「局域网设备同步」功能（2.22.0 / 322，本地未推送）

- **需求**：同一局域网内两台设备之间同步配置（换机搬家）。
- **关键复用**：项目已有 `BackupManager.exportBackup(File)` / `importBackup(File)`，导出的是 JSON（收藏 + 历史 + 全部 Hawk 设置）。同步不需要另造数据格式——直接把这个 JSON 传到对端再 `importBackup` + `AppUtils.relaunchApp(true)` 即可，与「数据备份还原」行为完全一致。
- **权限零新增**：manifest 已有 `INTERNET` / `ACCESS_WIFI_STATE` / `CHANGE_WIFI_MULTICAST_STATE`（普通权限，不弹窗）。且 `network_security_config.xml` 是 `<base-config cleartextTrafficPermitted="true"/>` + `usesCleartextTraffic=true`，所以明文 HTTP 访问局域网 IP 不会被 Android 9+ 拦截（**否则 HttpURLConnection 到 http://192.168.x.x 会直接失败**）。
- **协议**（`app/src/main/java/com/github/tvbox/osc/util/LanSyncManager.java`，纯 JDK，无第三方依赖）：
  - 发现：UDP 广播端口 **45127**，payload `TVBOX_LAN_SYNC|设备名|httpPort`，发送端每 1.5s 发一次（同时发 `255.255.255.255` 与 `x.x.x.255` 子网广播，防部分路由器拦截）；接收端监听 4s 收集并按 ip+port 去重、排除本机。**接收 UDP 广播必须拿 `WifiManager.MulticastLock`**，否则常被系统过滤收不到。
  - 传输：发送端起极简 HTTP 服务（`ServerSocket`，端口 8099~8103 依次尝试），只支持 `GET /config`（返回 JSON）和 `GET /ping`；接收端 `HttpURLConnection` 下载到 cacheDir 再 import。
- **UI**：`DeviceSyncDialog` + `dialog_device_sync.xml`（仿 `dialog_backup.xml` 样式），两个按钮「发送配置 / 接收配置」；发送端显示本机 `IP:端口`、对方取走后回调显示来源 IP；接收端扫描结果动态生成 TextView 列表可点，另提供手动输入 `IP:端口` 兜底（广播被拦时用）。设置页在「数据备份还原」下方新增 `llDeviceSync` 入口。
- **注意点**：`exportBackup`/`importBackup` 内部有 Room DAO 查询，**必须在子线程调用**（已在 LanSyncManager/Dialog 里放到 Thread）；Dialog `dismiss()` 覆写里 `stopServer()`，防止服务泄漏。

## 修复设备自动发现不可靠（2.22.1 / 323，本地未推送）

- **用户反馈**：自动发现设备"总是发现不了，老是要手动输 IP，特别麻烦"。
- **根因**：原发现机制**纯靠 UDP 广播**（`255.255.255.255` + `x.x.x.255`）。Wi-Fi 普遍有 AP 隔离 / 路由器广播过滤 / Android 对广播的限制，接收端基本收不到包，所以只能手动输 IP。
- **修复**：发现改为「**UDP 广播监听 + 子网主动探测**」双保险（`LanSyncManager.discover` 内并行跑两个阶段，汇总线程发现设备静置 2.5s 后提前返回，否则等到 `timeoutMs`）：
  1. 阶段一 `udpListenPhase`：保留原 UDP 广播监听（广播不被拦时 1~2s 即现）。
  2. 阶段二 `subnetScanPhase`：**主兜底**。对同网段 `/24` 每个 IP（1~254，排除本机）用 80 线程池并发 `HttpURLConnection` 探测候选端口 8099~8103 的 `GET /ping`，连接/读超时各 300ms；谁回 `"ok ..."` 谁就是发送端。**单播 TCP，不受广播拦截影响**，这是可靠发现的关键。
  - `pingPort()` 解析 `/ping` 体首行：`"ok 设备名"` 取设备名，仅 `"ok"` 回退 "TVBox 设备"。`addUnique()` 按 ip+port 去重合并两个阶段结果。
- **配套改动**：
  - 发送端 `/ping` 体由 `"ok"` 改为 `"ok " + getDeviceName()`，让子网探测发现的设备也带友好名。
  - 发送端广播 socket 绑定到本机 WiFi 地址（`ds.bind(localIp, 0)`），确保广播从正确网卡发出（部分机型不绑定收不到）。
  - 对话框 `discover` 超时由 4000 → **8000ms**（给子网探测留足时间），提示语加"自动探测子网"。
- **静态校验**：括号平衡（跳过字符串/注释）通过；manifest 权限与 `network_security_config` 明文放行均齐全，新增 `SocketTimeoutException/TimeUnit/AtomicBoolean` 导入。

## 修复订阅源同步后在「订阅管理」看不到（2.22.2 / 324，本地未推送）

- **现象**：同步提示成功、收藏/历史也回来了，但 `SubscriptionActivity`(订阅管理) 列表是空的。
- **根因**：`BackupManager.importBackup` 对所有 settings 统一用 `editor.putString("api_history", 原始字符串)` 直接写回 SharedPreferences。但 `api_history` 是 `List<Subscription>` 复杂对象，Hawk 存它时除值之外还会写一个**类型标记**键；只回写值、不回写类型标记，Hawk 反序列化 `Hawk.get(SUBSCRIPTIONS, ArrayList())` 时拿不到类型 → 退化成 `ArrayList<LinkedTreeMap>`（或空），`SubscriptionActivity` 读不到订阅。
- **修复**（`BackupManager`）：导出与导入都对 `HawkConfig.SUBSCRIPTIONS` 单独走 `Hawk` API——导出用 `Hawk.get` 取真实列表再 Gson 序列化为 JSON；导入用 `Hawk.put(SUBSCRIPTIONS, list)` 写回，**值与类型标记一起正确写入**。其余 settings 仍是原始类型直接回写（那些都是 String/int/bool 基础类型，不受影响）。新增 import `Hawk`/`Subscription`/`Gson`/`TypeToken`/`ArrayList`。
- **验证**：括号平衡（跳过字符串/注释）通过。`api_url`(当前源) 与 `live_url`(直播源) 本就是基础类型、已正常同步，本次只修复杂对象这一类。

## 修复订阅源同步后仍看不到（2.22.3 / 325，本地未推送）——真正的根因

- **2.22.2 修复方向对，但导出/导入"形态不匹配"导致仍失败**：2.22.2 把 SUBSCRIPTIONS 改为"导入走 `Hawk.put`"，但导出端写的是 `settings.add(SUBSCRIPTIONS, JsonParser.parseString(gson.toJson(subs)))` → 在备份 JSON 里 `api_history` 是 **JSON 数组**；而导入端读的是 `settings.get(SUBSCRIPTIONS).getAsString()` → 对 JSON 数组调 `getAsString()` 会直接抛 `IllegalStateException: This is not a JSON Primitive`，被 catch 吞掉 → `subs` 为 null → `Hawk.put` 从未执行 → 订阅源始终没写回。这就是"同步成功但订阅管理仍空"的真相（用户二次反馈"还是看不到"）。
- **修复**（`BackupManager`）：
  - 导出：`settings.addProperty(SUBSCRIPTIONS, new Gson().toJson(subs))` —— 把订阅列表存成 **字符串** primitive（而非 JsonArray）。
  - 导入：`getAsString()` 之前先判断形态，`isJsonArray()` 直接 `new Gson().fromJson(el, type)`，`isJsonPrimitive()` 再 `getAsString()` 后解析 —— **两种形态都兼容**，避免再因形态问题静默失败。
  - 导入最终仍走 `Hawk.put(SUBSCRIPTIONS, subs)`，保证值+类型标记一起写回，`SubscriptionActivity` 重启后能 `Hawk.get` 读到。
- **教训**：备份 JSON 里复杂对象统一用"字符串 primitive"存最稳；导入端不要假设单一形态，先 `isJsonArray/isJsonPrimitive` 再解析，并避免把所有异常吞成静默失败（至少打日志或将失败暴露给用户）。
- **共用同一还原入口**：`数据备份还原`(`SettingActivity.doRestoreFromUri`, kt:123) 与 `局域网同步`(`DeviceSyncDialog`, java:183) 都调 `BackupManager.importBackup` → 2.22.3 一处修复覆盖两个功能。导出端 `doBackupToUri`(kt:101) 也走 `exportBackup`，同样被 2.22.3 修好。
- **备份文件版本兼容**：2.22.0/2.22.1 的导出循环把 `List<Subscription>` 当未知类型跳过 → 那些旧备份里**根本没有订阅源**，只能重新导出。2.22.2 起才有 SUBSCRIPTIONS（存为 JSON 数组）；2.22.3 导入端兼容 `isJsonArray` 与 `isJsonPrimitive`，故 2.22.2 备份也能正常还原订阅。重新构建后建议用 2.22.3 重新导出一次再还原最稳。
- **验证**：括号平衡（跳过字符串/注释）通过。

## 修复本地导入的订阅源同步后"无法读取本地配置文件"（2.22.4 / 326，本地未推送）

- **现象**：发送端的订阅源是用「订阅管理→本地导入」加的 JSON 文件（URL 形如 `file:///data/data/<pkg>/files/subscriptions/xxx.json`，存于发送端私有目录）。同步后接收端虽然能看到订阅条目（2.22.3 已修），但点开加载报 `ApiConfig.loadConfig` 的"无法读取本地配置文件"——因为同步只带了 URL 字符串，文件本体没传，接收端该私有路径下文件不存在。
- **根因**：本地订阅的"真实内容"在发送端私有目录，URL 是设备私有的绝对路径，无法跨设备复用；之前的备份/同步只序列化了 URL，没带文件内容。
- **修复**（`BackupManager`）：把本地订阅文件内容也打包进备份 JSON。
  - 导出：遍历 `SUBSCRIPTIONS`，对每个 `file://`/`content://` 订阅，用 `readLocalBytes(url)` 读内容 → 顶层新增 `localFiles` 对象，key=原订阅 url、value=Base64 内容（NO_WRAP）。
  - 导入：解析出 `subs` 后，若 `root` 有 `localFiles` 且该订阅 url 命中，则 `Base64.decode` → 写入接收端 `files/subscriptions/<md5(url).json>`（由 `localFileName(url)` 派生稳定不重名文件名）→ `sub.setUrl(Uri.fromFile(...).toString())` 重写成本机私有路径 → 再 `Hawk.put(SUBSCRIPTIONS, subs)`。
  - 辅助：`isLocalUrl` / `readLocalBytes`(file://走 FileInputStream, content://走 contentResolver) / `localFileName`(md5(url)+".json") / `md5`。导入端对单条失败 try/catch 跳过，不影响其余订阅。
  - LAN 同步与数据备份还原共用 `exportBackup/importBackup` → 一处修复同时覆盖两者；旧备份无 `localFiles` 则跳过（仍会留下设备私有 URL，需 2.22.4 重新导出）。
- **局限（已知、未做）**：仅处理订阅源(`SUBSCRIPTIONS`)的本地文件；若「当前影视源 API_URL」本身也是本地 `file://`/`content://` 配置，同步后同样会指向发送端私有路径而加载失败（`ApiConfig.loadConfig` 同一处报错）。如需彻底可一并处理 API_URL 本地文件，可后续扩展；本次按用户反馈仅修订阅源。
- **验证**：括号平衡（跳过字符串/注释）通过；`android.net.Uri`/`android.util.Base64`/流/MD5 导入齐全。`Subscription` 的 `url`/`name` 字段是**包级私有（无 public）**，跨包代码必须用 `getUrl()`/`setUrl()` 访问——首版 2.22.4 直接用 `sub.url` 导致 `compileReleaseJavaWithJavac` 失败（7 个错误），已 amend 改用 getter/setter 修正。

## 同步/还原后首页源不对的真正根因：Hawk 存储文件名是 Hawk2（2.22.6 / 328，本地未推送）
- **现象**：接收端同步后重启，订阅管理能看到订阅源，但**首页不是发送端本地导入的那个订阅源**；用户发现"必须再进一次订阅页并退出/返回，才切换到新订阅源"。
- **根因（关键，颠覆性）**：`BackupManager` 一直用 `getSharedPreferences("Hawk", ...)` 直接读写设置，但 **Hawk 2.0.1 的默认存储文件名是 `Hawk2`**（反编译 aar 确认：`HawkBuilder` 常量 `STORAGE_TAG_DO_NOT_CHANGE`，`javap` 见 `ldc // String Hawk2`）。
  - 导出：`sp.getAll()` 读的是不存在的 "Hawk" → 几乎所有基础设置（API_URL / HOME_API / …）**根本没被导出**。
  - 导入：基础设置走 `editor.putString` 写进 "Hawk" → **写错文件**，Hawk 读 "Hawk2" 拿不到 → 设置不生效。
  - 只有订阅走了 `Hawk.put(SUBSCRIPTIONS, subs)` → 写 "Hawk2" → 订阅能生效（所以订阅管理看得到）。
  - 用户"进订阅页再退出"才生效，正是因为 `SubscriptionActivity.onPause()` 里有 `Hawk.put(HawkConfig.API_URL, mSelectedUrl)`（写 Hawk2）。**这两条现象互相印证，直接锁定根因。**
- **附带发现**：Hawk 序列化是 `type#value` 包装串（`HawkSerializer`，分隔符 `#`），sp 原始值不是纯值 → 只把文件名改成 Hawk2 还不够：`isLocalUrl(包装串)` 会误判，本地文件打包不触发。且 Hawk 的 `put` 内部用 `commit()`（同步），而 BackupManager 用 `apply()`（异步）→ 导入后立即 relaunch 也可能丢。
- **修复**（`BackupManager`）：
  - 新增常量 `HAWK_PREF = "Hawk2"`，两处 `getSharedPreferences` 都改用它。
  - `API_URL`/`LIVE_URL` 单独处理：导出用 `Hawk.get(key,"")` 取**真实值**再判断 `isLocalUrl` + 打包 `localFiles`；导入用 `restoreLocalFile` 重建文件后 **`Hawk.put(key, 真实值)`**（不能走 editor，会绕过 Hawk 序列化）。
  - 其余设置项（含 HOME_API）：导出/导入**原样搬运 Hawk 的序列化串**（`editor.putString`），含类型信息，List/Set 等复杂对象也能无损还原，且无需知道具体类型。
  - `editor.apply()` → **`editor.commit()`**（同步落盘），避免导入后立即重启丢设置。
- **验证**：括号平衡通过；无残留 `getSharedPreferences("Hawk"`；`HAWK_PREF` 两处使用；`commit()` 生效。
- **版本**：2.22.5 → 2.22.6，versionCode 327 → 328（app/build.gradle + update.json 同步）。
