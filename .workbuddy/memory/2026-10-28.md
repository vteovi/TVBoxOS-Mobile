## 平板大屏播放/详情页改左右分栏（2.23.0 / versionCode 331）

- **需求**：平板大屏端非全屏播放页参考 TV 版（`D:/Project/Box-main`，电视专用）做成「左边一小块播放 + 右边影视详情」，但不照抄电视端的焦点链，保持触屏交互。
- **参考项目实测**：`Box-main/app/src/main/res/layout/activity_detail.xml` 的非全屏形态 = 顶部一行 `[海报 ivThumb][previewPlayerPlace 530x300][右侧标题/元数据/简介/按钮]`，下面是线路行 + 选集网格；`previewPlayer` 是根布局的直接子 View，用固定 margin/尺寸盖在占位区上，`toggleFullPreview` 只切换 MATCH_PARENT 与保存的 LP。
- **本项目落地**：新建 `app/src/main/res/layout-sw600dp/activity_detail.xml`
  - `llLayout` 垂直 → 顶部横向 `[previewPlayerPlace 权重1.15][右侧信息列 权重1]`（标题+详情>>、数据源 chip、无痕图标、操作按钮贴底、分隔线），下方 ScrollView（权重1）放 线路 + 选集。
  - **关键约束**：sw600dp 变体里所有 id 必须与 `layout/activity_detail.xml` **同名同类型**（ViewBinding 字段类型以默认布局为准），否则运行期 `findViewById` 强转 `ClassCastException`。已用脚本比对 23 个 id：无缺失、无多余、无类型不一致。
  - `previewPlayer` 初始 `invisible`，等代码算好位置再显示，避免首帧全宽 300dp 闪一下。
- **代码**（`DetailActivity.java`）：
  - `setupTabletPreview()`：`Utils.isTablet()` 判定后给 `previewPlayerPlace` 挂 `addOnLayoutChangeListener`（只在宽度变化时重算）。
  - `applyTabletPreviewSize()`：按占位区宽度算 `height = width*9/16` 写回，再 `post(layoutPreviewOverPlace)`。
  - `layoutPreviewOverPlace()`：用 `getLocationInWindow` 与根布局坐标**做差**算 margin（不关心中间被 LoadSir 多包一层），给 `previewPlayer` 设 `FrameLayout.LayoutParams`，并同步 `windowsPreview`。
  - `toggleFullPreview()`：平板退出全屏不再直接用旧 LP，改为先复位再 `applyTabletPreviewSize()` 重算（旋转后尺寸会变）。
- **为什么不做 layout-land**：DetailActivity 声明了 `configChanges`（orientation|screenSize|smallestScreenSize...），旋转不重建 Activity，`layout-land` 不会生效；所以顶部结构静态给出，尺寸靠运行时算。
- **验证**：XML 可解析；DetailActivity 括号平衡；id/类型比对通过；dimens 全部存在（顺手把不存在的 `dp_16` 换成 `16dp`）。
- **版本**：2.22.8 → 2.23.0，versionCode 330 → 331（`app/build.gradle` + `update.json` 同步），`更新记录.md` 已追加 2.23.0 段。

## 2.23.2 / versionCode 333 —— 修复平板旋转后尺寸变小

- **现象**：平板横屏 → 竖屏 → 横屏，播放器高度与右侧详情栏高度都变小（回不到首次尺寸）。
- **根因**：`DetailActivity` 声明 `configChanges`，旋转不重建 Activity，而 `previewPlayerPlace` / `ll_info_column` 的高度是运行时按当时宽度写死的**像素值**（非 dp），旋转后没人重算；且 `BaseActivity.onConfigurationChanged` 会调 `AutoSize.autoConvertDensity` 改 density，旧像素值语义进一步错位。
- **修复**：
  1. 重写 `onConfigurationChanged()` → `super` 后 `post(applyTabletPreviewSize)`（density 已更新，下一帧拿到新宽度）。
  2. layout 回调条件从「仅宽度变化」放宽为「宽度变化 **或** `isTabletPreviewSizeMatched(width)` 为 false」，并在回调里 `post` 而不是直接改 LP（避免 layout 中 requestLayout 警告）。
  3. `applyTabletPreviewSize()` 末尾再 `post` 一次校验：若下一帧 `place.getWidth()` 与本次不同就再算，避免停在旋转中间态。
  4. 宽度为 0 时最多重试 5 帧（`tabletSizeRetry`），防死循环。
- **提交** `f50ef13`（未推送），版本 2.23.1 → 2.23.2。

## 2.24.0 / versionCode 334 —— 选集改「按屏宽动态列数」网格，整页上下滚动

- **需求**：详情页选集原来一行横向左右滑，二三十集要拖很久；改成按屏宽排布、整体从上到下排列，上下滑动。
- **做法**：
  - `DetailActivity.initView()`：`mGridView` 从 `V7LinearLayoutManager(HORIZONTAL)` 换成 `androidx GridLayoutManager(this, 4)`，装饰从 `LinearSpacingItemDecoration(20)` 换成 `GridSpacingItemDecoration(span, 8dp, true)`；`seriesAdapter = new SeriesAdapter(true)`（原来 false=固定 120dp 宽）。
  - **两个必须项**：`setHasFixedSize(false)`（wrap_content 依赖内容测高）+ `setNestedScrollingEnabled(false)`（否则 RecyclerView 吞掉垂直手势，外层 ScrollView 滚不动）。
  - `Utils.getSeriesGridSpanCount(context, widthPx, list)`：`widthDp = widthPx/density`，`minItemDp = avgNameLen*12 + 20 + 10`，`span = clamp(widthDp/minItemDp, 2, 10)`。**注意**：`BaseActivity.getSizeInDp()` 对 smallestScreenWidthDp<600 固定 360dp，所以手机横竖屏 dp 宽都是 ~360（列数不变，UI 整体缩放）；平板返回真实 screenWidthDp，列数才真正随屏宽增长（8~10 列）。
  - `updateSeriesGridSpan()`：宽度变化（layout listener）或 `setNewData` 后重算；列数变了要 remove+重建 ItemDecoration（间距按 span 算边距）。数据为空时直接 return，避免先按空数据算窄再跳回。
  - 定位当前集：网格在页面整体滚动里，RecyclerView 自己不能滚 → `scrollToPosition` 失效，改 `child.requestRectangleOnScreen(rect,false)` 让外层 ScrollView 滚；`findViewByPosition` 为 null 时 post 一帧再试。
- **连带修复**：`SeriesAdapter` 网格模式显式把 item 宽度设回 MATCH_PARENT（原来只处理固定 120dp 分支，复用 view 会残留宽度）；`AllVodSeriesRightDialog.onDismiss` 不再 `setGird(false)`（详情页本身就是网格）。
- **布局**：两份 `activity_detail.xml` 的 mGridView 删掉 `app:tv_*`、`tools:orientation`，`tools:layoutManager` 改 GridLayoutManager。⚠️ 用脚本删属性时把 sw600dp 里 `tools:orientation="horizontal" />` 的 `/>` 一并删掉了导致 XML 不合法，已修——以后删 XML 行要检查是否带自闭合标签。
- 提交 `11f70fc`（未推送），版本 2.23.2 → 2.24.0。
