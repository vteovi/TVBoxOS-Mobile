## 搜索页跟随「横版海报」设置（v2.26.2，commit f118333）
- 现象：设置里开启「横版海报」后，首页/收藏/历史都变成 16:9 卡片，但搜索结果仍是「左图右文」竖版行（`item_search.xml`，固定 120dp 高 + 图按 110×160 裁剪），风格不一致。
- 关键实现点：
  - 首页/收藏/历史的横版效果来自 `item_grid.xml` 根布局 `RatioShadowLayout`（`onMeasure` 里按宽算高：横版 16:9、竖版 2:3，读 `HawkConfig.LANDSCAPE_CARD`），列数由 `Utils.getPosterSpanCount()`（横版按 300/400/720dp 目标列宽取整，竖版按 150/180/220dp）决定。
  - 搜索结果是 `FastSearchActivity`（声明 `configChanges`，旋转不重建）→ `FastSearchAdapter` + `item_search`，用 androidx `LinearLayoutManager` 跑在 TvRecyclerView 上。
- 改法：
  - 新增 `res/layout/item_search_landscape.xml`：`RatioShadowLayout`（`app:hl_cornerRadius="14dp"`，margin 4dp）→ ImageView 铺满 + 底部 `bg_gradient_black_b2t` 渐变，里面 `tvName` / `tvSite` / `tvNote`。
  - `FastSearchAdapter`：**布局在构造时按 Hawk 决定**（`super(landscape? R.layout.item_search_landscape : R.layout.item_search, ...)`），并用 final 字段锁住同一判断分支——否则 convert 里再读 Hawk 可能与已 inflate 的布局不一致。横版下图片直接 `centerCrop` 铺满（`DefaultConfig.checkReplaceProxy`），不再走 `RoundTransformation` 固定像素裁剪（会把横图切变形）。
  - `FastSearchActivity`：横版用 `GridLayoutManager(this, Utils.getPosterSpanCount(this))`，竖版仍 `LinearLayoutManager`；覆写 `onConfigurationChanged` 重算 `spanCount`（因为不重建）。
  - 顺手给 `ApiConfig.get().getSource()` 加了 null 保护（原来直接 `.getName()` 可能 NPE）。
- 校验：XML 可解析；两套布局 id 集合一致（ivThumb/tvName/tvNote/tvSite）；Java 括号平衡；Kotlin 花括号平衡、Utils 无重名 import。
- 其他搜索入口（`QuickSearchDialog` / `SearchSuggestionsDialog` / `item_quick_search_lite`）都是纯文字，无海报，无需改动。
- 版本 2.26.2 / versionCode 339；待用户 push main + tag v2.26.2 由 CI 出包。

  - 发布任务 checkout 加 `fetch-depth: 0`（切分支 + rebase 需要完整历史）。
  - 顺序永远应是 **先 push main，再 push tag**，否则 Release 里的 changelog 与实际代码不符。
- 验证方式（可复用）：`git clone --bare` 本地仓库当 remote，克隆出来后按步骤模拟。跑了两种场景都通过：① tag == main；② tag 领先 main（复刻本次失败场景），远端 main 最终拿到 update.json=2.26.3。

## 修复分类页「筛选」点筛选后不生效（v2.26.4 / versionCode 341，commit 1e5af50）
- 链路：`GridFragment.showFilter()`（右下角 FAB `btn_filter`）→ `GridFilterDialog`（底部弹窗，`dialog_grid_filter.xml`）→ 点「筛选」dismiss → `OnDismissListener` 里 `selectChange` 为 true 才回调 → `page=1; initData()`。
- 筛选值来源：`MovieSort.SortFilter.values` 是 `LinkedHashMap<显示名, 真值>`，点击必须提交 **values** 而不是 keySet；`sortData.filterSelect` 存 `key -> 真值`。请求侧：type3 走 `sp.categoryContent(tid, pg, true, filterSelect)`；type0/1 加 `.params(filterSelect)` + `f=JSON`；type4 用 `ext=base64(JSON)`。
- 查出的问题（都改了）：
  1. **缓存 key 不含筛选条件**（`grid_cache_<source>_<sortId>`）→ 筛选后 `initData()` 先读缓存铺旧数据（=筛选前），是"看起来完全没反应"的主因；且筛选结果会覆盖无筛选缓存，下次进分类看到串味数据。→ `cacheKey()` 追加 `TreeMap(filterSelect).toString().hashCode()`，并给 `initData(skipCache)` 加参数，`applyFilter()` 用 `initData(true)`。
  2. **`setData()` 只在 `gridFilterDialog == null` 时调用一次** → 重开对话框不重建选项、不还原选中高亮，用户看不出选了啥。→ `showFilter()` 每次 `setData(sortData)`。
  3. 选中态靠匿名类里 `View pre` 记上一次点击的 View，脆弱。→ `GridFilterKVAdapter` 改为持有 `keys`（真值列表）+ `selectedValue`，`convert` 里按 position 比对后 `sl.setSelected()`，点击后 `notifyDataSetChanged()`。
  4. 重置按钮 `filterSelect = new HashMap<>()` 换对象 → 改用 `clear()`。
  5. 切子分类（`changeView`）/返回上级（`restoreView`）不清筛选条件 → 新增 `clearFilterSelect()`。
  6. **竞态**：旧的分页/筛选响应回来会覆盖新列表。→ `SourceViewModel` 加 `volatile int listSeq`，`getList` 开头 `++listSeq`，各回调先判 `seq != listSeq` 就 return（type3 在 spThreadPool 里也要判）。
  7. `initData()` 直接 `ApiConfig.get().getHomeSourceBean().getApi()` 可能 NPE → 判空走 showEmpty。
- 注意：`filters` 为空时点 FAB 现在会 toast「当前分类不支持筛选」，不再静默无反应。
- 静态校验：4 个 Java 文件括号平衡、`R.id` 引用都在对应布局内（`mFilterKv` 在 `item_grid_filter.xml`）、无残留旧构造调用。


## 修复弹窗打开后状态栏文字变白（v2.26.5 / versionCode 342）
- 现象：浅色模式下点首页右下角「筛选」，状态栏文字/图标从深变白、看不清；深色模式无变化（本来就是白）。
- 根因：`CustomDialogStyle`（`res/values/styles.xml`）带 `android:windowFullscreen=true` → 弹窗 window 拿到 `FLAG_FULLSCREEN`，系统把它当"拥有状态栏的窗口"，状态栏图标改用**弹窗窗口**的 appearance；弹窗没有像 `BaseActivity.initStatusBar()` 那样 `statusBarDarkFont(!Utils.isDarkTheme())`，于是退回默认白色图标。
- 修法（`BaseDialog.java`，一次修好所有 BaseDialog 子类）：onCreate 里 `clearFlags(FLAG_FULLSCREEN)`（attach 前就去掉，避免弹窗刚出现时闪白）+ `show()` 调 `syncStatusBarWithHost()`：再清一次 flag，并把**宿主 Activity** 的 `WindowCompat.getInsetsController(...).isAppearanceLightStatusBars()` 同步给弹窗窗口。
- **别用 App 主题判断状态栏深浅**：详情页/直播页状态栏是黑的（`statusBarColor(R.color.black)`），按主题判断会把它们改错；必须读宿主实际外观。
- 弹窗布局没有任何 statusBar 高度补偿（grep `status_bar_height` 无结果），清掉全屏标记不会破坏布局；底部弹窗 wrap 高度不受影响。
- API 校验：`androidx.core:core 1.13.1` 确认存在 `WindowCompat.getInsetsController(Window,View)`、`WindowInsetsControllerCompat.isAppearanceLightStatusBars()/setAppearanceLightStatusBars(boolean)`（javap 验过）。
