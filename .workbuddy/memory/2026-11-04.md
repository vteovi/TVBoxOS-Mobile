## v2.28.8 修复：切回分栏后上滑不再加载（Android 手机/平板都复现）

现象：进首页 → 往左滑到后面几个分栏 → 上滑到底 → 往右滑回前面的分栏 → 再上滑，加载到已缓存内容末尾就再也不加载，必须重启 App。

根因（设备无关，大屏更明显因为一页数据≈一屏）：
首页分栏 `HomeFragment.initViewPager` 用 `FragmentStatePagerAdapter`（默认 `offscreenPageLimit=1`）。
滑过 2 个以上分栏后，前面分栏的 Fragment 被 `destroyItem` 移除，但 `fragments` 列表仍持有实例，
`getItem()` 返回同一个实例 → 重建视图。此时 `BaseLazyFragment.mIsFirstVisible` 已是 false，`init()` 不再执行，于是：
1. `listResult.observe(this, ...)` 在生命周期销毁时已被自动移除 → 之后 `getList` 的响应 **没人接收**，`mLoading` 卡 true，BRVAH 停在 loading，永久不加载。
2. 重建时 LiveData 会向新订阅者 **重放最后一次值**：若按"新的一页"处理 → `page++` 越过 `maxPage` → `setEnableLoadMore(false)`；若重放的是旧的失败结果(null) → 弹"没有更多了"并关掉加载更多。

修复（`ui/fragment/GridFragment.java`）：
- 观察者提为字段 `mListObserver`，新增 `bindListResult()`，在 **每次 onCreate** 补挂（首次创建时 sourceViewModel 为 null 自动跳过），不再只依赖 `init()`。
- 新增 `mWaitingList`（已发请求等回调中）+ `mListReqAt`：观察者里 `if (!mWaitingList) return;` 丢弃所有重放/迟到回调（比"实例身份比对"更稳，连 null 重放也拦得住）。
- 三处请求发起点收敛到 `requestList()`（`initData` / `onLoadMoreRequested` / `autoFillViewport`），统一登记等待状态。
- 新增 20s 超时兜底 `mListTimeoutRunnable`：网络超时 10s，20s 无回调说明回调丢了 → 复位 `mWaitingList/mLoading` + `resetLoadMoreState()`，避免任何情况下的"永久卡死"。
- `onFragmentResume()`：不再无脑清 `mLoading`；请求在途就继续等（重建后由 LiveData 补投），仅超时或状态不一致时复位；已到底（`page > maxPage`）时保持"加载更多"关闭，不白请求越界页；补一次 adapter/LayoutManager 绑定；`mAutoFillCount` 打满后重置一次额度。
- `SourceViewModel.getList` type==3 分支 catch 里补 `listResult.postValue(null)`：spider 抛异常时原来一个结果都不回，调用方永远等不到回调（同一类卡死源）。

## 经验
- 复用 Fragment 实例的 `FragmentStatePagerAdapter` 写法（`getItem` 返回预先构造好的实例）会让"生命周期销毁→重建"这条路径绕过所有 `init()` 里做过的事；凡是在 `init()` 里 `observe(this)` 的，都要能在 onCreate 时重挂。
- `LiveData` 对新订阅者重放旧值是真坑：任何 `observe` 回来后的第一个回调都要用"是否真的在等"来过滤，不能只看内容。
- `Gradle` 在本仓库沙箱内可正常跑（`compileArm64v8DebugJavaWithJavac`；`:app:compileDebugJavaWithJavac` 会因为多 flavor 报 ambiguous）。

## v2.28.9 修复：导入本地 JSON 再切回在线订阅后，首页数据源被换掉

现象（用户报）：导入本地 JSON → 切回 `https://box.iqinu.com` → 点首页海报，本该进聚合搜索，却进了详情页且没有内容。复测有时正常（取决于当前是哪个站点/哪张海报）。

根因（确定会发生，不是偶发）：
- `ApiConfig.parseJson` 选首页站点：`String home = Hawk.get(HawkConfig.HOME_API, ""); sh = getSource(home); if (sh == null) setSourceBean(firstSite);`
- `HOME_API` **全局唯一**，且 `setSourceBean` 每次都覆盖它。
- 导入本地 JSON → 解析时把 `HOME_API` 改成本地站点的 key；切回在线 → 用本地 key 在新配置里找不到 → **退回 firstSite**（用户原来选的站点被丢掉）。
- firstSite 不一定支持快速搜索（`quickSearch` 默认 1 但可被配置置 0），于是 `GridFragment` 点海报的分支从"进聚合搜索"变成"进详情"；该站点又不支持按 id 取详情 → 空白页。

修复：
- `ApiConfig`：新增 `HOME_API_OF_PREFIX = "home_api_of_"` + `mCurApiUrl`，**按订阅配置分别记忆**选过的首页站点（`home_api_of_<md5(配置地址)>`）；`parseJson` 优先取本配置记住的 key，其次才用全局 `HOME_API`，最后才 firstSite。
- `GridFragment` 点击：用 `video.sourceKey` 校验数据源是否还存在；已失效则用标题走聚合搜索（进详情必然空白）。顺带把 `video.tag.equals` 改成 `"folder".equals(video.tag)` 防 NPE。
- `SourceViewModel`：`getDetail/getSearch/getQuickSearch/getPlay` 补 `sourceBean == null` 保护（原来 `sourceBean.getType()` 直接空指针）；`getDetail` 的 spider 异常分支补 `detailResult.postValue(null)`（原来详情页永远停在加载中）。
