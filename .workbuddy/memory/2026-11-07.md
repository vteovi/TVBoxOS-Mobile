# 2026-11-07

## v2.31.0 设备同步：接收配置时合并收藏/历史（不再覆盖）

需求：用户觉得「接收配置」把收藏和历史直接覆盖不好，希望既保留本机现有记录，又拿到发送端的记录。

根因：`DeviceSyncDialog.fetchFrom()` 调 `BackupManager.importBackup(out)`，而 `importBackup` 里对
`collects` / `records` 都是 `dao.deleteAll()` 后逐条 insert。

实现（commit `6b2b34a`，版本 2.30.0/360 → **2.31.0/361**）：
- `BackupManager` 新增 `enum ImportMode { REPLACE, MERGE }`；`importBackup(File)` 保持 REPLACE（设置页「数据备份还原」用），
  新增 `importBackup(File, ImportMode)`；`lastImportSummary`（volatile，后台写主线程读）供 UI 显示统计。
- 合并算法：先读本机全表按 `(sourceKey, vodId)` 建 `HashMap` 索引 → 外来每条：
  - 本机没有 → insert，并把 `dao.insert()` 返回的 rowId 回填 `setId()`（备份里出现重复 key 时后续 update 才能定位主键）；
  - 两边都有且外来 `updateTime` 更大 → `dao.update(exist)`（历史更新 dataJson 播放进度；收藏更新 name/pic，空字段不覆盖本机）。
  - **不能用 INSERT 直接怼**：`vodCollect` / `vodRecord` 表都没有唯一约束，主键是 autoGenerate id，直接 insert 会插出重复海报。
- `VodCollectDao` / `VodRecordDao` 各补一个 `@Update int update(...)`。
- 合并完调 `trimHistoryToLimit()`：按 `HISTORY_NUM`（`HistoryHelper.getHisNum`，30/50/70）`dao.reserver(hisNum)` 裁剪。
- `dialog_device_sync.xml` 加 `cbMerge` CheckBox（默认勾选）+ 说明文字；`DeviceSyncDialog.fetchFrom()` 按勾选传 MERGE/REPLACE，
  成功后展示「收藏新增 X 条、更新 Y 条 / 历史新增…」。
- **只有收藏/历史区分模式；设置和订阅源仍覆盖**（配置类以发送端为准）。

设计取舍：
- 并集语义下「删除」不会跨设备同步（A 删了、B 还留着，下次同步又回来）。想让两台完全一致 → 取消勾选走覆盖。
- 文件备份还原（SAF）保持覆盖，因为那是「恢复」语义（重置/换机后要精确还原），未加开关。

## v2.32.0 设备同步：订阅源改为并集合并 + 全表去重

需求：用户接着 2.31.0 提「这个订阅源也改成这个吧，就是设备同步时保留现有的订阅源」，随后补一句「还有订阅源要加入去重」。

根因：`importBackup` 里 `SUBSCRIPTIONS` 一直走覆盖，`API_URL` / `LIVE_URL` / `HOME_API` 也一律用发送端值。
只合并列表而不保住当前源，会出现「列表选中 A、实际加载 B」（2.28.9 同类问题）。

实现（版本 2.31.0/361 → **2.32.0/362**）：
- `ImportMode.MERGE` 语义扩展：订阅列表并集 + 订阅/收藏/历史全表去重 + 当前源保留。
- `importBackup`：MERGE 时 `HOME_API`、`API_URL`、`LIVE_URL` 本机已有非空值就 `continue`（本机没配过才用发送端）；其余设置照旧覆盖。
- 新增 `mergeSubscriptions(incoming, localFiles)` 返回 `{新增, 去重}`：
  - 去重键 `subscriptionKeys(url, localFiles)`：在线用归一化 URL（scheme/host 小写、去尾 `/`、留 port/query，规则对齐 `SubscriptionActivity.subscriptionKey`）；本地文件用打包内容 / 本机文件内容的 MD5 + URL 键。
  - 三层判重：本机列表内部、两端之间、发送端列表自身；`Map<String,Integer>` 键→索引，重复时按 `rank(checked=2 / builtIn=1)` 保留更该留的一条。
  - 外来条目**先判重再决定是否** `restoreLocalFile()` 重建文件（避免无用副本），重写到本机路径后再查一次；追加项强制 `checked/top/builtIn=false`。
- REPLACE 路径也过 `dedupSubscriptions(subs)`，覆盖导入不会带进重复项。
- 摘要加「订阅新增 X 项、去重 Y 项」；`DeviceSyncDialog` 注释/成功文案、`dialog_device_sync.xml` 开关文案同步更新；`更新记录.md` 加 2.32.0 段落。
- 文件备份还原（SAF）走 `importBackup(File)` = REPLACE，仍精确覆盖。

设计取舍：
- 并集语义下本机当前源不变，发送端当前订阅作为普通条目加入，用户想用手动切；新设备要完全一致 → 取消勾选走覆盖。
- 本机列表内部重复也清掉（用户明确要求去重），但只删键完全相同的条目，空 URL 不擅自删。
- 未把 `LIVE_HISTORY` / `HISTORY_SEARCH` 等其它列表纳入合并，范围只限用户点名的订阅源与既有收藏/历史。

校验：本机仍无 JDK/SDK（java 不可用），只能静态检查——括号平衡（先剥字符串再删 `//` 注释）、方法定义/调用、XML、版本号、CI changelog 抽取（5 条 415 字）全部通过；**未做真实编译**。
`update.json` 保持 2.31.0 不动（2.32.0 未发版、Release 不存在），发版时由 CI 回写。
