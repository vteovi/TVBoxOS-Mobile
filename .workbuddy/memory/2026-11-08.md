## v2.32.1 首页「启动后闪一下、卡片位置突然变」

用户现象：打开软件后往上滑一下，过几秒首页会闪一下，卡片位置像突然变了。

三段成因（都指向"启动时的静默刷新打断浏览"）：

1. **GridFragment 第一页静默刷新整表替换**
   - `initData` 先铺 `grid_cache_<sourceKey>_<sortId>` 的缓存（立即能滑），随后 `requestList()` 拿网络第一页。
   - `handleListResult` 里 `shownFromCache=true` 时走 `replaceDataKeepingScroll()`：`gridAdapter.setNewData()` → `notifyDataSetChanged`，所有可见卡片重新 bind（海报若 URL 变了会先回占位图 → 闪）。
   - 「最近更新」类分类的新片插在最前面，新旧 id 序列不同 → 整片换位置。
   - 更糟的是 `replaceDataKeepingScroll` 的恢复条件写成 `firstPos > 0`：只滑一点点时第一行还露着（`findFirstVisibleItemPosition()==0`），条件不成立 → 偏移不恢复，列表视觉上"往上跳一下"。

2. **HomeFragment 分类数据回来时整页重建**
   - `sortResult` observer 用 `oldSortIds.zip(newSortIds).all { 相等 }` 判断结构，**顺序变化**也算不同 → `initViewPager(absXml)` 会 `fragments.clear()` + 换 adapter，所有分栏 Fragment 重建、列表回顶并闪一下。
   - 重新 `install(...)` 还可能让 TabLayout 的当前项复位。

3. **`initData()` 无条件 `showLoading()`**
   - LoadSir 会把整块 `contentLayout`（含 ViewPager 和所有 RecyclerView）从布局树上摘下来换成 loading 页，再 `showSuccess()` 放回去 —— 已有内容时调用就是一次可见闪烁 + 重新布局。

修法：
- `GridFragment`：新增 `userBrowsing()`（`canScrollVertically(-1)` 或 `findFirstVisibleItemPosition()>0`），用户已离开顶部时**不替换列表**，只写缓存（`Hawk.put(cacheKey())` 在判断之前，已经落盘），下次进入该分栏再生效。
- `replaceDataKeepingScroll`：`firstPos > 0` → `firstPos >= 0`；offset 改用 `getDecoratedTop(first) - paddingTop`（`getTop()` 不含 item margin/decoration）。
- `HomeFragment`：结构判断改成「id 集合」比较（`toSet()`），集合相同就不重建；顺序也相同时才把 `mSortDataList` 换成新对象（拿最新的 filters/name），顺序不同时保留旧列表保持 tab 与 fragment 对应。
- `initData()`：`if (fragments.isEmpty()) showLoading()`，已渲染过分栏不再切 loading 页。

## v2.32.2 分栏切回保持滚动位置（并入 2.32.1 未发布版本）

用户：首页第一个分栏滑到第二个，再滑回第一个，会闪一下并跳到最顶部；要求"原来在什么位置回来还是什么位置"。

原因：`GridFragment` 完全没有保存滚动位置。切走时 `onFragmentPause()` 是空实现；滑回来 `onFragmentResume()` 里只补 observer / 补 autoFill / 重建 LayoutManager。ViewPager 重新 attach fragment view 时 RecyclerView 会丢锚点（或 `applyGridLayoutManager()` 重设 LayoutManager），直接从第一条重新布局 —— 表现为闪一下 + 回顶。

改法（`GridFragment`）：
- 新增 `mSavedFirstPos` / `mSavedOffset`，`saveScrollState()` 记录 `findFirstVisibleItemPosition` + `getDecoratedTop(first) - paddingTop`；在 `onFragmentPause()` 和 `onDestroyView()`（被 FSPA 销毁前）各存一次。
- `restoreScrollState()`：`cur == saved && offset 相同` 时直接 return（不打扰用户刚滑的新位置），否则 `scrollToPositionWithOffset`；目标位置按 `getItemCount()-1` clamp，防数据变少时越界。
- `onFragmentResume()` 末尾先同步调一次（下一轮 layout 直接落到正确位置，避免先画一帧顶部），再 `post` 一次兜底。
- `initData()` 是主动回顶部（换分类/筛选/切源），清空记忆，否则下次 resume 会被旧位置拽回去。
- `autoFillViewport()` 增加 `getChildCount()==0` 守卫：切回瞬间列表还没布局，`canScrollVertically` 恒为 false 会被误判「一屏没填满」多发一次分页请求。

校验：本机无 JDK/SDK，仅静态检查（括号、符号引用、版本号、changelog 6 条 586 字）。未真实编译。
