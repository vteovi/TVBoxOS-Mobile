## v2.32.9 修复按返回键 IndexOutOfBounds（Index -1 out of bounds for length 8）

崩溃：`MainActivity.onBackPressed(MainActivity.kt:166)` → `ArrayList.get(-1)`。

**成因**：`onBackPressed` 用 `childFragments[homeFragment.tabIndex]` 取当前分栏，
而 `HomeFragment.tabIndex` 直接返回 `mBinding.tabLayout.currentItemIndex`。
DslTabLayout 里它是 `dslSelector.dslSelectIndex`（`DslTabLayout.kt:327`），**默认值 -1**；
`HomeFragment.initViewPager()` 每次重建分栏都是 `tabLayout.removeAllViews()` → 重新 `addView` → `install(vp, tab, true)`，
这段窗口内 tabLayout 没有选中项（-1），此时按返回键就用 -1 当下标 → 崩溃。
（用户日志：启动 10 秒后按返回，正是分类数据回来、分栏刚重建完的时刻。）

**改法**：
1. `HomeFragment.tabIndex`：`currentItemIndex` 落在 `fragments.indices` 才用，否则改用 `mViewPager.currentItem` 并 `coerceIn(0, size-1)`；`fragments` 为空返回 -1；
2. `MainActivity.onBackPressed`：`childFragments.getOrNull(tabIndex)`，取不到走 `confirmExit()`（等价于「回主页 tab」分支）。

版本 **2.32.9 / 371**（PATCH）。`assembleArm64v8Release` BUILD SUCCESSFUL（1m46s），产物 41M，
签名 CN=TVBoxOSC，sha256 `ee695523…f22a`。提交 `0a69ec8`（dev，本地）。
**教训：DslTabLayout 的 `currentItemIndex` 会在 removeAllViews 后变成 -1，任何「取当前 tab」的地方都要兜底或用 ViewPager.currentItem。**

**新坑（重要）**：用户 2026-11-12 在全局 gitconfig 里加了
`url."https://gh-proxy.com/https://github.com/".insteadOf = "https://github.com/"`
（为了加速 **fetch**）。推送直接报 `remote: No anonymous write access. fatal: Authentication failed`——
gh-proxy 只提供只读镜像，**push 必须走 github.com 本体**。

对策：推送前临时 `git config --global --unset-all "url.https://gh-proxy.com/https://github.com/.insteadOf"`，
推完立刻 `--add` 回原值。⚠️ **别把 unset 和再 add 写在同一串命令里还让它被超时/中断杀掉**——
本次就因为一次 `timeout` 触发 SIGTERM，恢复语句没执行，导致全局配置被留在「已删除」状态，
之后所有 fetch 都直连 github.com（当时又正好被墙）白等 20s。以后用
`git config --global --unset-all ... ; <push> ; git config --global --add ...` 但把网络那步放进**后台任务**，
或者用 `GIT_CONFIG_GLOBAL` 指向临时配置（保留 credential.helper）。

**连通性现状**：`github.com:443` 时好时坏（本次 19:36 可推送、19:39 CI 正常、19:41 起又 reset/超时）；
`gh-proxy.com` 稳定可读；`api.github.com` 一直正常。fetch 走 gh-proxy 没问题（`git fetch origin main` 即走重写）。

### 23:05 — v2.33.2：修「手机播放页退出全屏后选集区空白」

现象（用户确认）：手机布局播放页进全屏 → 按系统返回键退出 → 「线路」「选集」下面的内容全没了，页面到此为止。

排查结论（`DetailActivity.toggleFullPreview()`）：
- 全屏时把 `mGridView` / `mGridViewFlag` 设 GONE；退出时的显隐恢复写在
  `playFragment.changedLandscape()`、`setRequestedOrientation`、ImmersionBar、`previewPlayer.setLayoutParams` **之后**，
  这几步任何一个出岔子（方向请求被打断/布局参数没设上）就会把两个列表永久留在 GONE。
- 即便恢复到 VISIBLE，退出那一帧 RecyclerView 还没量出宽度（方向刚切回来），
  只 post 一帧算列数可能算错、甚至量成 0 高 → 也是「空白 + 页面到底」。
- `onBackPressed` 里的 `mGridView.requestFocus()` 同步执行时，ScrollView 会把一个 0 高度的列表当焦点目标，
  可能把页面滚到空白处。

改法：
1. 显隐恢复提到方法**最前面**（紧跟 `fullWindows` 取反之后），再动播放器与方向。
2. 新增 `relayoutSeriesAreaAfterFullscreen()`：下一帧算列数，120ms 后再校验，若「有数据但高度 ≤ 0」
   就重建 `GridLayoutManager` 强排，并对 RV 父容器 + `llLayout` 一起 `requestLayout()`。
3. `onResume()` 调 `restoreSeriesAreaIfHidden()`：非全屏且线路非空时，这两个列表不该是 GONE，异常就恢复 + 重排。
4. 退全屏的 `requestFocus()` 改成 `post` + 仅列表可见时执行。
