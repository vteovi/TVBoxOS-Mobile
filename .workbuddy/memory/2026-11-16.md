## 搜索页「热门搜索」空白修复（v2.34.9 / 385）
- 根因：`FastSearchActivity.hotWords` 只用腾讯 `https://node.video.qq.com/x/api/hot_search`，实测该接口返回纯文本 `Not Found`，JSON 解析必抛异常 → 热词区永远空。
- 方案：`loadHotWords()` = 先 `renderHotWords(buildDefaultHotWords())` 用内置词库随机取 18 条立即渲染；再 `fetchOnlineHotWords()` 并发拉豆瓣 `movie.douban.com/j/search_subjects?type=movie|tv&tag=热门`，任一返回 ≥6 条就覆盖成实时热词，失败静默保留内置。
- 新增 `app/src/main/res/values/arrays.xml` 的 `default_hot_search_words`（29 个长期有效影视名）。
- 豆瓣必须带浏览器 UA（OkGo 默认 UA 会被拒）；片名用 `cleanHotWord()` 去 `(预告片)` 之类的括号备注。
- 教训：`Edit` 工具改 CRLF 文件的长段落会因 LF 不匹配报 not found → 改用 Python `newline=''` 按行号替换；替换注释块时 `i-2` 偏移要按实际行数算，否则残留一个 `/**`。

## 大屏搜索页启动崩溃修复（v2.34.10 / 386）
- 现象：Pad（22081283C, Android 14, sw600dp）进搜索页即崩：`UninitializedPropertyAccessException: lateinit property mBinding has not been initialized @ FastSearchActivity.initView`。
- 根因：APK 里 `layout/activity_fast_search` 除了默认 `res/Lk.xml` 还混进了一个 `(sw600dp) res/P5.xml` —— 2.34.2 存档分支那套「左侧 64dp 导航柱 + 分栏」的老布局。它 `include` 的布局与当前资源表对不上，大屏 inflate 直接抛异常；`BaseVbActivity.initVb()` 把异常 `printStackTrace()` 吞了，`mBinding` 没赋值，崩溃点被推迟到 `initView()` 首行。
- 中间产物里其实找不到这个文件（`app/build` 下只有 packaged_res 的默认版本），是 aapt2 增量链接把旧配置留在了 resources.arsc 里 → 只能 `clean` 重建。
- 诊断手法（有效）：`aapt2 dump resources <apk>` 看某 layout 有几条配置；`aapt2 dump xmltree --file res/xx.xml <apk>` 反编译可疑布局；`apkanalyzer dex code --class <cls> <apk>` 看 dex 里类的真实方法/字段（比 dexdump 快很多）。
- 修法：① clean 全量重建（变体消失，已验证只剩默认一份）；② `initVb()` 失败改为抛 `RuntimeException(..., e)` 不再静默；③ `FastSearchActivity` 覆写 `initVb()` 直接用生成绑定类 inflate，绕开泛型反射。
- 教训：切分支后改布局/加资源，出包前先 clean，否则 aapt2 会保留别的分支的资源变体；崩溃报 "mBinding 未初始化" 一律先查资源变体，别查代码。
