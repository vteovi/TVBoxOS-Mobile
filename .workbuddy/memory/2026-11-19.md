
## 龙门影视详情「暂无数据」排查（v2.36.1 / 391）
- 源信息（从加密订阅解密得到，AES CBC：hex → `$#key#$` + 尾部 13 位 iv，key=123456 pad 到 16）：站点 `csp_sp_龙门影视`，type 3，api `csp_AppYsV2`，ext `http://movie.iqinu.com/api.php/v1.vod`。
- 实测接口：`?ac=list` 开放无鉴权；`?ac=detail&ids=` 返回 41 字段但**无 vod_play_url**；真正详情是 `ext + "/detail?vod_id="`，且**必须带 `;LoamenWebKit/524` 结尾的 UA**，否则 `{"code":400,"msg":"认证失败"}`；带 UA 时返回 `data` 对象内含 `vod_play_from`/`vod_play_url`。
- 反编译 `lm261103.jar` 的 `AppYsV2`：`detailContent` 按 ext 分支拼 URL（含 `api.php/app`/`xgapp` → `video_detail?id=`；含 `.vod` → `/detail?vod_id=`；否则 `?ac=detail&ids=`）；`h(url)` 生成 UA，未命中 host 白名单时是 `Dart/2.14 (dart:io);LoamenWebKit/524`（实测可通）。`init(ctx,ext)` 用 `ext.split("###")`，`c()` 返回 `b[0].trim()`。
- 结论：源站详情按 UA 放行，App 侧拿不到数据。用户对照 `D:/GitHub/Box-main` 正常。
- 兜底实现：`SourceViewModel` 新增 `isDetailEmpty()`/`fallbackDetail()`/`normalizeDetailJson()`，蜘蛛返回无播放地址时按 ext 直连一次并归一成 `{list:[...]}`；同时打印 `spider detail:` 原始响应。
- 工具经验：`dexdump -d classes.dex` 可看常量与调用链；`aapt2`/`apkanalyzer` 之外，解密 TVBox 加密订阅做源站核对很快。

## 部分机型首页整屏空白（连顶部标签都没有）根因与修复（v2.36.5 / 395）
- 用户反馈：红米 Note 7 Pro、红米 5 Plus、Redmi Pad 上「站点推荐」首页整屏空白；D:/GitHub/Box-main(TV 版) 与 D:/Project/TVBoxOS_Portrait 均正常。
- **根因（SourceViewModel）**：`spThreadPool = newSingleThreadExecutor()`（单线程），而 getList / getDetail / getPlay / quickSearch 的 spider 调用**全部没有超时**。任意一次卡住（老机型冷启动 jar 解压慢、弱网、源站不响应）→ 永久占用唯一线程 → 排在后面的 getSort 永远不执行 → `sortResult` 从不回调 → `observe` 不触发 → `mSortDataList` 空 → `initViewPager` 整体跳过 → **连 tabLayout 都没有子 View**（不是布局问题、不是 jar 加载问题、不是图片问题）。这也解释了「豆瓣热播同样空白」：整页压根没渲染。
- 修复：
  - 新增 `sortLoadPool`（独立单线程），`getSort` 的 type3 分支改用它，不再与列表/详情/播放抢同一队列。
  - `spThreadPool` 由单线程改为 `newFixedThreadPool(4)`，单次卡死只占一个线程。
  - `HomeFragment` 新增 `renderTabsPlaceholder()`：`init()` 与 `initData()` 各调一次，先用 `sort_cache_<key>` 缓存渲染，无缓存则 `adjustSort(key, empty, true)` 画一个「主页」占位；有内容时不再 `showLoading()` 盖住。
  - 新增 `sortDataReady` 标记；兜底超时 20s→12s。**注意**：原 `sortTimeoutTask` 用 `mSortDataList.isEmpty()` 判断，占位渲染后列表非空会跳过兜底，必须改用 `sortDataReady`。
- 验证结论：两版对比（Portrait / Box-main）在首页布局、AutoSize、LoadSir 包装、getSort 超时上一致；差异就是本仓库后加的线程池拆分缺失（homeRecThreadPool 只解决了 self-deadlock，没解决队头阻塞）。
- 产物：`TVBox-Mobile-v2.36.5-arm64v8.apk`、`TVBox-Mobile-v2.36.5-armv7a.apk`（老机型 32 位 ROM 用 v7a）。

## 老机型只有「主页」一个标签（v2.36.6 / 396）
- 现象：老机型选完订阅源，首页只剩「主页」标签，下面「暂无数据」；新机型正常。选站点推荐也一样。
- 定位依据：解密订阅后发现**全局 spider 有 jar、每个站点的 jar 字段为空** → `getSpider` 走 `jar.isEmpty()` → `jarKey="main"`，命中 `ApiConfig.loadJar` 注册的类加载器，所以不是"重复下载"问题。
- **真因**：`JarLoader.loadClassLoader` 判断「订阅可用」的窗口是 `count < 5` × `Thread.sleep(200)` = **1 秒**。老机型首次 dex 优化几 MB jar 要数秒，拿不到 `com.github.catvod.spider.Init` 就直接 `return false` → 整份订阅判死 → 所有源返回 `SpiderNull` → `homeContent` 为空 → `sortList` 空 → `adjustSort` 只剩 `my0`。主页退回豆瓣，豆瓣在老机型上又取不到 → LoadSir 空态「暂无数据」。
- 连带死循环：`ApiConfig.loadJar` 在 **md5 校验已通过**（文件完好）但 load 失败时仍然 `cache.delete()` 重下，把好文件删掉，下次继续失败。
- 修复：
  - 窗口 5→50 次（10s），注释说明这是「慢 ≠ 坏」。
  - `ApiConfig.loadJar` 整体改为 `jarLoadExecutor` 后台线程执行（原先全程在主线程，是当初把窗口压到 1s 的原因），`doLoadJar` 包 try/catch 保证必回调；`HomeFragment.dataInitOk/jarInitOk` 加 `@Volatile`。
  - md5 通过但加载失败 → 不再删缓存，直接 `callback.error()`；只有 `useCache` 路径（未校验 md5）才怀疑文件损坏。
  - `JarLoader.load(cache, key)` 重载：按 jarUrl 的 md5 注册类加载器并同时注册 "main"；`loadJarInternal` 找不到 `<key>.jar` 时回退复用 `csp_<key>.jar`。
  - `getSort` 超时 15s→25s；加 `getSort spider=<类名>` 日志。
- 教训：**判断「订阅可用」的等待窗口不能按"快机器"设**；任何 dex 加载都必须离开主线程，否则会为了防 ANR 把超时压到不可用。

## jar 下载/加载改多线程并发（v2.36.7 / 397）
- 用户反馈 2.36.6 明显好转后，提出「加载下载一次可能会卡住，能不能多线程」。定位到剩余瓶颈都在 `ApiConfig.loadJar`：
  1. `jarLoadExecutor` 是 `newSingleThreadExecutor`；首页 initData 每次（切源/重试/回前台）都会触发 loadJar，一次加载等 10s dex，后面全排队。
  2. `jarLoader.load()` 在 OkGo 的 `onSuccess` 回调线程里跑，占住下载线程 10s。
  3. 下载直接覆盖 `csp_<md5>.jar`，中途失败会把好文件弄坏 → 永远重下。
- 改造：
  - 线程池 1→3（`newFixedThreadPool(3)` 命名 jar-loader，daemon、低优先级）。
  - **单飞**：`ConcurrentHashMap<String, JarLoadTask>` 按 spider 字符串去重，进行中的加载把新回调挂到 `waiters`，结果 `dispatchJarResult` 统一派发一次；`JarLoadTask.add()` 在 done 后返回 false，外层 remove+重试一轮。
  - 下载完成回调里只做落盘，`jarLoadExecutor.execute` 再加载（新增 `loadJarFileAsync`）。
  - **加载序号** `issueLoadSeq()`/`load(cache,key,seq)`：`committedSeq` 比对，seq 更小直接丢弃 → 快速切源时旧任务不会清掉新配置的类加载器。
  - **JarLoader.load 加 `loadLock` 串行化**（类加载器是整表 clear+重建，并发会互相清）；`loadClassLoader` 拆出 `doLoadClassLoader` 并共用同一把可重入锁。
  - 下载改 `xxx.jar.tmp` 先写、`looksLikeJar()` 校验文件头（PK / dex\n，>256B）、再删旧+rename；`loadJarInternal` 同步下载同样走 tmp。
- 关键约束：**dex 加载必须串行（整表替换），但下载可以并行**；不要为了并发去并发化 load()。
- 产物：TVBox-Mobile-v2.36.7-arm64v8.apk / -armv7a.apk，commit `9b39d1f0`，未推送。

## 切订阅后「慢几拍」+ 首页/搜索仍用旧源（v2.36.8 / 398）
- 现象：订阅页切换订阅 → 回首页还是上一个源的内容；点海报进聚合搜索也还是旧源结果；几秒后才对。
- 两个原因：
  1. `SubscriptionActivity` 选中时只记地址，`Hawk.put(API_URL)` 在 onPause 才写，配置要等回首页 `loadConfig` 才下载 → 秒级等待。
  2. `ApiConfig` 是单例，`MainActivity` 用 CLEAR_TASK 重建但**进程不重启**，新配置 `parseJson` 完成前 `sourceBeanList`/`mHomeSource` 仍是旧订阅 → 首页 `renderTabsPlaceholder()` 用 `homeSourceBean.key` 渲染旧缓存标签，`SearchHelper.getSources()` 也返回旧源。
- 修复：
  - `ApiConfig.prefetchConfig(url)`（走 `jarLoadExecutor` 后台线程）：订阅选中即下载配置写缓存（**只写缓存不 parse**），并 `prefetchSpiderJar()` 预下 `csp_<md5(url)>.jar`（`.prefetch.tmp` + rename），回首页 `loadJar` 直接命中。
  - `ApiConfig.resetForSwitch()`：清 `sourceBeanList`/`mHomeSource`/`spider`/`mCurApiUrl`，在 `SubscriptionActivity.finish()` 切换分支里调用（顺便把 Hawk API_URL 提前写盘）。
  - `ApiConfig.getLoadedApiUrl()` + HomeFragment `configMatchesCurrentSubscription()`：`mCurApiUrl != Hawk API_URL` 时先 `loadConfig()` 并 return，不渲染旧源。
  - 抽出 `resolveConfigUrl()`（loadConfig/prefetch 共用），修掉不带协议地址被拼成 `http://`（空串）的老 bug。
- 注意：`resetForSwitch()` 必须在 `finish()` 里、`mBeforeUrl != mSelectedUrl` 时调用一次；不要放 `onPause`（每次切后台都会触发，会把刚加载好的新配置又清掉）。
- 产物：v2.36.8 arm64v8 / armv7a，commit `34eaa419`，未推送。
