## 与 D:\WorkBuddy\TV-fongmi 的播放能力对比（结论）

用户反馈：同一批源，fongmi 能播，本项目的部分源"能搜到剧、点播放黑屏/报错"。

模块级差异（fongmi 多）：`thunder`（迅雷模块）、`tvbus`（P2P 直播 aar）、`chaquo`（Python 运行时）、`nodejs`（NDK）、独立 `catvod`（含 `Proxy.java` 播放代理）。
本项目：`app + player + quickjs`，P2P 只有迅雷（`thunder.jar` + `com.p2p.P2PClass`）。

能力级差异（按对"播不了"的影响排序）：
1. **特殊 scheme 无分发**（已补）：fongmi `Source` 有 7 个 extractor（Push/Video/WebView/Strm/Thunder/TVBus/YouTube），处理 `webview://`、`video://`、`push://`、`magnet/ed2k`、YouTube；本项目全代码搜不到 `webview://`/`video://`/`push://`/`tvbus`。
2. **无 MPV**：fongmi 有 `MpvPlayerEngine`（全格式 FFmpeg），本项目 ExoPlayer 2.18.7 + IJK，HEVC 10bit / AV1 / 特殊封装解不了。
3. **脚本运行时**：fongmi 有 QuickJS + Python(chaquo) + Node.js；本项目只有 QuickJS → py/node 源连列表都出不来。
4. **Spider 基类 API**：fongmi 有 `proxy()/proxyUrl()/action()/danmaku()` + 内置 `js`；本项目只有 `proxyLocal()`。
5. **P2P 直播**：本项目无 tvbus，rtmp 弱。

已确认**不是**问题的点：
- `/proxy?do=` 路由通（`RemoteServer.serve` → `ApiConfig.proxyLocal` → `JarLoader.proxyInvoke` → jar 内 `com.github.catvod.spider.Proxy.proxy` 静态入口）。
- 注意：fongmi 这份代码**没有 `androidx.media3` 的 gradle 依赖声明**（`libs.media` 只是 `androidx.media:media`），不能直接编译；搬播放器代码会缺依赖，只能作参考。

## 本轮修复 v2.36.10 / 400（commit `5440d83a`，未推送）
针对"能搜到剧但点播放黑屏"，补两处低成本高收益项：

1. `PlayFragment.playUrl()` 开头加 scheme 分发：
```java
if (lowerPlayUrl.startsWith("webview://")) { initParse("", false, "", target); return; }
if (lowerPlayUrl.startsWith("video://")) { playUrl(target, headers); return; }
```
2. `PlayFragment.initParse()` 里统一解包 `webview://`（避免 parse=1 时 WebView 把伪协议当真实网址加载）。
3. `Spider` 基类补：
```java
public Object[] proxy(Map<String,String> params) throws Exception { return proxyLocal(params); }
public String action(String action) throws Exception { return "{}"; }
```
新版 jar 爬虫统一用 `proxy(...)`，基类缺失时走代理的源会 `NoSuchMethodError`。

产物：`TVBox-Mobile-v2.36.10-arm64v8.apk` / `-armv7a.apk`，`CI=true ./gradlew assembleRelease` 通过。

## 对比 D://Project//Box-main：补齐"超级解析"（v2.36.11 / 401）
- 用户症状：能搜到剧、点播放立即报"视频播放出错"（带错误码），**换任何播放内核都一样** → 判定不是解码，是地址/代理层。
- 定位路径：两个项目播放代码同源（PlayFragment/Spider/JarLoader/RemoteServer 端口 9978 全一致），差异在：
  - 播放引擎：Box-main 有 media3 1.3.1 + nextlib(FFmpeg 全格式) + 阿里云播放器；本项目 Exo 2.18.7 + 音频 FFmpeg 扩展 + IJK
  - **/proxy 路由**：Box-main 同时支持 `do=`(jar spider) 和 **`go=`**；本项目只有 `do=`
  - Box-main 有 `util/parser/SuperParse`（"超级解析" type=4）+ `JsonParallel` + `util/Proxy`；本项目完全没有
  - DoH 默认、IPyLoader（Python 源）、Spider.liveContent 也是 Box-main 多出来的
- 关键链路：订阅里的网页源被包装成 `proxy://go=SuperParse&flag=..&url=base64`，`DefaultConfig.checkReplaceProxy` 换成 `http://127.0.0.1:9978/proxy?go=..`，交给 WebView 嗅探。本项目 `/proxy` 无 `go=` 分支 → 空响应 → 嗅探空 → 报错。
- 已移植：`util/parser/{SuperParse,JsonParallel,Utils}.java` + `util/Proxy.java`（CRLF）；`RemoteServer` 加 `go=` + 抽出 `getProxy()`（rs 为 null 返回 500，避免 NPE）；`ApiConfig.addSuperParse()`（有 parses 时插到 index 0 作默认解析）；`PlayFragment.doParse` 加 type=4 → `parseMix(pb,true)`，另加 `rsJsonJX()` 与"无网页解析器时退回纯 json 并发"；`stopParse()` 里调 `SuperParse.stopJsonJx()`。
- 注意：`SuperParse.parse` 用 `parseFlag+"123"` 查 flag 表（必然查不到 → 用全部解析器），这是 Box-main 原样逻辑，保留；`flagWebJx` 也用同 key，loadHtml 能对上。
- 坑：RemoteServer 行替换时多留一个 `}` 导致"需要 class/interface"编译错，删掉即可。
- 待验证：装 v2.36.11 试之前报错的源；若仍报错，需用户给源名+错误码（说明是地址 403/header 问题）。另提醒：两个 App 同时运行会抢 9978，后启动者自增到 9979，而 spider 硬编码 9978 的地址会打到另一个 App。

## 播放失败体验改造：错误码 + 不自动调外部播放器（v2.36.12 / 402）
- 用户反馈：播放失败后被自动弹到外部播放器，外部播放器报 `网络请求失败（Unexpected NullPointerException: Attempt to invoke virtual method 'boolean andro...`。该文案**不在本项目里**（全项目 grep 无"网络请求失败"），来自被调起的外部 App，说明它拿到地址后自己挂了（多为本地代理地址/需要 header）。
- 根因：`PlayFragment.setTip("视频播放出错")` 里会自动 `mController.mPlayerBtn.performClick()`，而该按钮在 `PlayerHelper.getExistPlayerTypes()` 全部类型里循环，包含 >=10 的外部播放器（MX 10 / Reex 11 / Kodi 12 / TVBox 13 / VLC 14）。
- 改动：
  - 新增 `player/…/PlayerError.java`：静态快照 + `describeMediaError(what,extra)` / `describeExoError(code)` 中文解释；在 `IjkPlayer.onError(mp,what,extra)`、`ExoMediaPlayer.onPlayerError(PlaybackException)`、`player/AndroidMediaPlayer.onError` 第一现场写入。
  - `PlayFragment.errReplay()`：先 `autoRetry()` 重试一次，仍失败则 `setTip("播放失败，点此查看详情")` + `showPlaybackErrorDialog(detail)`，`LOG.i("play error: ...")`。
  - 弹窗选项：重试当前集 / 换个内置播放器 / 用外部播放器打开 / 复制错误信息；提示文字可点击重开；`playErrorDialogShowing` 防叠加。
  - `VodController.switchToNextPlayer(boolean includeExternal)`：自动切换传 false（只在内置 0/1/2 间循环）；外部播放器仅用户点选时走 `openExternalPlayerManually()`（proxy:// 会拦截提示）。
  - 记录 `mCurrentHeaders` 供外部播放器用。
- 坑：`mPlayerBtn.setOnClickListener` 在 initView 里，方法不能插在它前面，否则"需要 class/interface"报一堆错；要插到类级别（放到 `updatePlayerCfgView()` 前）。
- 外部播放器识别：`PlayerHelper.getPlayersInfo()` 里 >=10 全是外部；`getExistPlayerTypes()` 返回已安装。

## 播放失败真因：本地代理端口 -1（v2.36.13 / 403）
- 用户案例：奶酪秒播 / 荐片|多线 的「后会有期」；出错地址 `http://127.0.0.1:-1/proxy?do=m3u8&url=https%3A%2F%2Fv.fengbao14.com/.../index.m3u8`，Exo 报 2004 HTTP 状态码异常。
- 关键：端口是 **-1**。这类 spider 用 `com.github.catvod.Proxy.getUrl(true)` 把 m3u8/ts 绕回宿主代理；该类端口默认 -1，宿主必须在本地服务启动后 `Proxy.set(port)`（fongmi 在 `server/Server.java` 里 set）。本项目**没有这个类**，所以永远是 -1，播放器连不上不存在的端口 → 换内核也一样。
- 修复：
  - 新增 `app/src/main/java/com/github/catvod/Proxy.java`（port/getUrl(boolean)，getUrl(false) 用 LocalIPAddress）。
  - `ControlManager.startServer()` 成功后 `Proxy.set(RemoteServer.serverPort)`（含已启动分支），`getAddress()` 加 mServer==null 兜底（返回 127.0.0.1:serverPort，不再 NPE）。
  - `JarLoader` 在 createClassLoader 后、以及 `com.github.catvod.spider.Init.init` 之后再 `bindProxyPort(classLoader)` 反射 set（jar 自带同名类也能写中）。
  - `PlayFragment.playUrl` 兜底：含 `127.0.0.1:-1`/`localhost:-1` 时递归一次换成真实端口（不能直接改形参，否则匿名内部类引用报"必须是最终变量"）。
  - `Spider` 基类补 `getProxy(boolean local)` → `com.github.catvod.Proxy.getUrl(local)`。
- 弹窗复制：v2.36.12 的弹窗 message 默认不可选中；现在 `dialog.show()` 后取 `android.R.id.message` 设 `setTextIsSelectable(true)` + 长按复制，动作项改名「复制到剪切板」。
- 环境提示：本机 curl/WebFetch 都取不到 erxiao.json（解析不了 ghp.ci），无法离线反编译订阅 jar，只能靠运行时验证。
